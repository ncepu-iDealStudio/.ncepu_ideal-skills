# 已有项目的增量更新规范（新增表 / 表结构变更 / 表下线）

> 适用场景：目标 Gin 项目的骨架**已经生成过**，现在用户提供了新的 DDL 或修改后的 DDL。
>
> 本规范配套 `resources/config/incremental_change_policy.json` 使用。**每次增量任务开始前必须先读策略文件**。

---

## 1. 三种场景与判定

| 场景 | 判定条件 | 技能动作 |
|---|---|---|
| **新增表** | 骨架已存在，该实体 5 类文件**全部不存在** | 按实体生成文件 + 幂等追加注册 |
| **表结构变更** | 骨架已存在，该实体**任一**文件已存在 | 先做字段级差异分析，再分层更新 |
| **表下线** | 用户明确要求移除/下线 | 只输出待删清单，**不执行删除** |

### 判定要点

- 骨架是否存在，看：`go.mod`、`main.go`、`internal/models/`、`apis/api_1_0/urls.go`
- **「用户又给了一遍建表 SQL」≠ 重新建表**：只要实体文件已存在，就必须走「表结构变更」
- 一次给多张表时**逐表判定**，允许同批混用
- 残留文件不成套（如只剩 `models/` 与 `dao/`）→ **先询问用户**

### 与 Flask 版的差异

| 项 | Flask | Gin |
|---|---|---|
| 实体文件数 | 7 类 | **5 类** |
| 分层 | Model / Controller / Service / Resource | Model / Dao / Service / Resource |
| 继承方式 | Service 继承 Controller | **内嵌组合**（Service 内嵌 Dao，Dao 内嵌 Model） |
| 注册点 | `api_1_0/__init__.py` | `apis/api_1_0/urls.go` |
| 注册工具 | 手写 marker 追加 | **已有 `merge_router_registry.py`**（优先复用） |
| 编译检查 | 导入自检 | **`go build ./...`**（最有力） |

## 2. `alter_table`：差异识别（强制）

### 2.1 取得旧结构

按优先级尝试，取到即停：

1. 用户提供的旧版 `CREATE TABLE` / `CREATE VIEW`
2. 项目内 `database/*.sql`
3. `internal/models/{entity_name}.go` 的 struct 定义（解析 gorm tag：`column` / `type` / `not null` / `default` / `primaryKey`）
4. `resources/demo_output/generated_context_*.json`（若项目由本技能生成，**context 就是最准确的结构基线**）
5. （**仅用户同意时**）`information_schema`

**取不到就问用户，禁止猜测差异。**

### 2.2 归一化后逐字段对比

| 归一化项 | 处理 |
|---|---|
| 大小写 | 忽略 |
| 字段顺序 | 忽略（但输出保持稳定排序） |
| 驼峰 vs 下划线 | 视为等价，**输出以 SQL 原字段名为准** |
| Go 类型 | `int64` 与 `int` **不视为等价** —— 影响 json 大数精度，必须显式报告 |
| `TINYINT(1)` / `BOOLEAN` | 等价（均映射 bool） |
| 软删 / 状态位 | 按最新 SQL 重新计算 |

### 2.3 输出差异清单（先给用户看，再动手）

```text
📋 结构差异：student（表）

风险等级：⚠️ HIGH

新增字段
  + Gender  string  `gorm:"column:gender;type:varchar(10)"`  性别

删除字段
  - Agenda  string  `gorm:"column:agenda;type:text"`  日程  ⚠️ 被 3 处引用

Go 类型变更
  ~ PhoneNumber  string → string（varchar(20) → varchar(500)）

gorm tag 变更
  ~ IsDelete  去掉 not null

确认继续？
```

**规则**：

- 差异清单必须先展示，用户确认后才动手
- `critical` / `high` 必须逐个确认
- `removed + added` 语义相近 → **先问是重命名还是删旧加新**
- **Go 特有**：字段改名会导致 struct 属性名变化，**所有引用该属性的代码都会编译失败**，必须全量列出

## 3. 影响面矩阵（速查）

| 变更类型 | `models/` | `dao/` | `services/` | `Resource.go` + `urls.go` | `apis/api_1_0/urls.go` | README |
|---|---|---|---|---|---|---|
| 新增字段 | 🔄 覆盖 | 🔄 覆盖 | 📝 待办 | 📝 待办 | — | 📝 待办 |
| 删除字段 | 🔄 覆盖 | 🔄 覆盖 | 📝 待办 | 📝 待办 | — | 📝 待办 |
| 改字段类型 | 🔄 覆盖 | 🔄 覆盖 | 📝 待办 | 📝 待办 | — | 📝 待办 |
| 改可空/默认/唯一/索引 | 🔄 覆盖 | 🔄 覆盖 | 📝 按需 | — | — | 📝 按需 |
| 主键变更 | 🔄 覆盖 | 🔄 覆盖 | 📝 待办 | 🔄 覆盖 | ⚠️ 可能变 | 📝 待办 |
| 软删字段变化 | 🔄 覆盖 | 🔄 覆盖 | 📝 **必须** | — | — | 📝 **必须** |
| 状态位增删 | 🔄 覆盖 | 🔄 覆盖 | ⚠️ 确认后追加 | 🔄 覆盖 | — | 📝 待办 |
| 视图定义变化 | 🔄 覆盖 | — | 📝 按需 | 📝 按需 | — | 📝 按需 |

图例：🔄 可覆盖 ｜ 📝 只输出待办（不覆盖）｜ ⚠️ 需用户确认 ｜ — 不动

### 3.1 三条最容易出事的同步规则

#### 规则一：状态位「同进同退」

`Resource` 的状态更新 handler、`urls.go` 的路由注册、`Service` 的业务校验**必须同步**。

Go 的特殊风险：**Resource 调用了 Service 里不存在的方法 → 编译直接失败**（比 Flask 的运行期 500 更早暴露，但也更容易被忽略为"先跳过"）。

```text
1. 展示待追加的 Service 方法片段
2. 取得用户明确同意
3. 只追加到 service 文件末尾
4. 追加后立即 go build 验证
```

#### 规则二：软删字段要改三处

- `models/`：字段定义（可覆盖）
- `dao/`：`Get` 的过滤条件、`Delete` 的软删分支（可覆盖）
- `services/`：**手写文件里的 GetList 过滤条件**（只能列待办）

#### 规则三：主键变更会穿透所有层

主键影响：`models` 的 `primaryKey` tag → `dao` 方法 → `services` 签名 → `Resource` 路径参数 → `urls.go` 的 `url_item` 模板 → 前端契约。

Go 特有：`urls.go` 里写的是 `/student/:auto_id`，参数名与 `Resource` 里 `c.Param("auto_id")` 必须**字面一致**，改一处漏一处会运行期取不到值。

## 4. 文件归属与覆盖规则

| 文件 | 标记 | 覆盖策略 |
|---|---|---|
| `internal/models/{Entity}.go` | `Code generated by` | 直接覆盖 |
| `internal/dao/{Entity}.go` | `Code generated by` | 直接覆盖 |
| `internal/services/{Entity}.go` | `【HAND-WRITTEN】` | **绝不覆盖**，输出待办 |
| `apis/api_1_0/{slug}/{Entity}Resource.go` | `Code generated by` | 重生成 CRUD，保留自定义 handler |
| `apis/api_1_0/{slug}/urls.go` | `Code generated by` | 直接覆盖 |
| `apis/api_1_0/urls.go` | marker 区块 | 幂等追加（用既有工具） |
| `internal/settings/`、`internal/globals/`、`internal/rpcServer/` | 无标记 | **完全不碰** |
| `configs/`、`utils/`、`cmd/`、`init/` | 无标记 | **完全不碰** |

**判定补充**：文件存在但没有生成标记 → 视为用户已手改，**禁止覆盖**。

### 4.1 确需向 Service 追加代码时

```text

原因：新增 status 字段，需要停用前的关联校验

────────────────────────────────

func (m *StudentService) ChangeStatus(pk int, status int) error {
    if status == 0 {
        // 停用前校验
```

## 5. `add_table`：注册与幂等（强制）

新表必须在 `apis/api_1_0/urls.go` 注册，否则路由 404。

### 5.1 注册位置

```go
import (
	"github.com/gin-gonic/gin"
	// ==AUTO_IMPORTS_START==
	student "study_flask_api/apis/api_1_0/student"
	// ← 在 END 之前追加
	// ==AUTO_IMPORTS_END==
)

func InitAPIRouter(engine *gin.Engine) {
	Api = engine.Group("api")
	// ==AUTO_REGISTRY_START==
	student.InitStudentRouterGroup(Api)
	// ← 在 END 之前追加
	// ==AUTO_REGISTRY_END==
}
```

### 5.2 幂等要求

**优先复用既有工具**：

```bash
python resources/tools/merge_router_registry.py <context.json> <urls.go>
```

该工具已实现：去重、排序、重复执行零 diff。

手工兜底时：

- 追加前检查 import 路径是否已存在
- 同一份 SQL 重复生成 → **零 diff**
- marker 被删除或改写 → **不自动修改**，输出待办并告警
- 追加后按 alias 排序，保持稳定 diff

## 6. 数据库迁移边界

技能**不做**：

- 执行任何 DDL
- 改写 `database/` 下的 SQL
- 接入 golang-migrate 等迁移框架
- **启用 GORM `AutoMigrate` 作为生产迁移手段**
- 删除或修改数据

技能**要做**：

- 给出 MySQL `ddl_hint`
- 提示发布顺序：加列先 DDL 后发代码；删列先发代码后 DDL
- 提示备份与回滚
- **明确说明**：`AutoMigrate` 只可用于开发环境快速验证结构，生产必须走 DDL（它会静默改表、可能丢数据、无法回滚）

## 7. 执行顺序（`alter_table`）

```text
1. 判定模式
        ↓
2. 取旧结构 → 归一化 → 逐字段比对 → 输出差异清单
        ↓
3. 用户确认（high/critical 必确认）
        ↓
4. 按影响面矩阵逐层更新
   ├─ 覆盖：models / dao / resource / urls.go
   ├─ 追加：apis/api_1_0/urls.go（用 merge 工具）
   └─ 待办：services / README
        ↓
5. **go build ./... 必须通过**（Go 无运行时容错）
        ↓
6. 输出报告（含 DDL 建议与待办清单）
        ↓
7. 用户执行 DDL（技能不执行）
        ↓
8. 验证
```

> ⚠️ 第 5 步是关键：Go 是编译型语言，任何字段改名/方法签名不一致都会**编译失败**。如果 `go build` 不通过，不能宣称完成。

## 8. 验证清单

```bash
# 1) 编译自检（最有力，暴露字段改名、签名不一致、import 缺失）
go build ./...

# 2) 静态检查
go vet ./...

# 3) 注册自检
#    启动后确认路由存在

# 4) 全量回归
python resources/tools/run_regression_pipeline.py

# 5) 变化字段最小冒烟
#    POST 写入 → GET 详情 → PUT 更新 → DELETE

# 6) 幂等自检：同一 SQL 再跑一次，确认零 diff（快照校验）
python resources/tools/check_snapshots.py
```

## 10. 与既有策略的关系

| 既有机制 | 在增量场景下的处理 |
|---|---|
| `generation_profiles.json` | 仍用于决定生成档位，不影响增量判定 |
| `router_registry_merge_strategy.md` | 增量的注册幂等**沿用**该文档，并优先复用 `merge_router_registry.py` |
| 文件冲突策略（跳过已存在实体文件） | **被本规范细化**：不再一律跳过，改为按文件归属分级处理 |
| `field_rendering_rules.md` | 渲染单个字段时仍遵循 |
| `check_snapshots.py` / `run_regression_pipeline.py` | 增量后**必须**重跑，用于验证幂等与回归 |
