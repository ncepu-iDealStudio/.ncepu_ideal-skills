# 单文件交付

> 由 SKILL.md「生成顺序」第 6 步引用：分页面与整体验收均通过后，执行该步骤时先读本文件。

单文件是便于下发、评审和归档的派生交付物。`spec/`、`src/` 和分页面文件继续保留，仍作为后续修改和重新生成的来源；不得因打包删除或覆盖它们。用户明确不需要单文件时可以跳过。

## 输出要求

- 输出位置：原型根目录，与 `spec/`、`src/`、`预览截图/` 并列。
- 默认命名：`<原型名>-完整交互原型.html`；项目已有明确版本号时保留版本号。
- 一个文件内包含全部已登记页面、公共 CSS、页面脚本、Mock 数据及交互所需的本地素材。
- CSS、JavaScript 和 Mock 数据直接内嵌；本地图片、字体等资源转换为 Data URL 或等效内嵌形式。不得保留指向 `src/`、`assets/` 或其他本地文件的运行时依赖。
- 多页面原型可使用页面注册表配合 `iframe srcdoc` 承载各页面；将原相对链接和 `location.href` 跳转改写为单文件内部导航。
- 提供最小导航能力：总览、主要端侧入口、页面选择、返回。导航层不得遮挡原型主体或改变页面业务交互。
- 在 `README.md` 中登记单文件名称、打开方式及用途。

## 打包边界

- 只打包导航地图中已经确认并生成的页面，不补造页面或业务状态。
- 保留 PC 端、移动端及各状态页原有布局和交互，不为打包重新设计页面。
- 外部网络资源无法可靠离线使用时，应先改成本地内嵌资源；无法内嵌时在交付说明中明确依赖，不得声称"完全离线"。
- 单文件由当前分页面机械生成。需求或页面修改后，先同步 MD 和分页面，再重新生成单文件，禁止只修改打包结果。

## 单文件验证

必须从最终单文件本身打开验证，不能用分页面测试结果代替：

1. 页面注册数量与导航地图及已生成页面数量一致。
2. 搜索单文件，确认不存在 `src/`、`assets/` 等本地相对资源依赖；允许页面名称仅作为内部导航标识。
3. 从各主要端侧入口进入，至少走通一条完整的跨页面业务流程，并检查内部导航、返回和状态变化。
4. 检查内部返回、页面选择、弹窗、输入、反馈等关键交互；浏览器控制台不得出现阻断使用的错误。
5. 将单文件最终状态截图直接写入 `预览截图/`，命名如 `单文件完整交互原型-验证.png`。
6. 验证失败时回到 MD 或分页面修正，再重新打包；不要直接在单文件中打补丁。
