# requirements_analysis 使用说明

本文件夹存放**需求分析与设计**相关的技能与参考资料。它们是技能**本体**，不针对某个 AI 工具保存安装副本；用哪个工具，就把对应技能目录装到该工具的 skills 目录，再在对话中调用。

| 内容 | 类型 | 说明 |
| --- | --- | --- |
| `it-requirement-analysis/` | 技能 | 业务需求 → PRD、用户故事、验收标准 |
| `brainstorming/` | 技能 | 技术方案头脑风暴 → 设计规格 |
| `database-schema-designer/` | 技能 | 数据模型设计 → 建表脚本 + 设计文档 |
| `spec-kit/` | 开源工具 | GitHub 官方 SDD 工具包（完整规格驱动流水线） |
| `superpowers-zh/` | 技能集 | 20 个中文工作流技能，本仓库里的唯一本体 |
| `关于开源需求分析技能.md` | 参考资料 | 各类开源 SDD 工具对比与选型 |

---

## 1. it-requirement-analysis（需求分析）

**主要支持**：DSH、Cursor、WorkBuddy 等（技能名 `requirement-analysis`）。

以 **DSH** 为例：

1. 把 `it-requirement-analysis/` 整个目录复制到项目的 `.dsh/skills/` 下（目录名保持不变）：

   ```bash
   cp -r it-requirement-analysis <你的项目>/.dsh/skills/
   ```

2. 在 DSH 对话里直接说需求，例如：

   ```text
   用 requirement-analysis 技能分析：做一个发票 OCR 识别与自动填表系统。
   ```

3. 技能会先追问关键维度（架构方式、使用对象、处理量、准确率等），用选择题回答；随后先给需求摘要，你选 A/B/C 再展开对应的 PRD、用户故事或 AI 方案。

> 在 Cursor 中用法相同，把目录放到 `.cursor/skills/it-requirement-analysis/` 即可。

## 2. brainstorming（方案设计）

**主要支持**：通用工作流技能（Claude Code、Cursor、DSH、Codex CLI、Copilot CLI 等均可加载）。

以 **Claude Code** 为例：

1. 把 `brainstorming/` 放到 `.claude/skills/brainstorming/`（或项目的 skills 目录）。
2. 在对话中提出想法：

   ```text
   用 brainstorming 技能：为这个报销系统设计 OCR 识别方案。
   ```

3. 技能先把任务分为**探路 / 有界 / 架构级**三类；架构级会逐步提问、给出 2–3 个方案权衡，分节展示设计，经你确认后写出设计规格文档（默认 `docs/superpowers/specs/`）。
4. 设计确认后，交给 `writing-plans` 技能生成实现计划。

> 关键约定：**未经你批准，技能不会开始写代码**。

## 3. database-schema-designer（数据库设计）

**主要支持**：Cursor、Claude Code。

以 **Cursor** 为例：

1. 把 `database-schema-designer/` 复制到 `.cursor/skills/database-schema-designer/`（需带 `SKILL.md` 和 `references/`）。
2. 在 Cursor 对话里说明业务，例如：

   ```text
   用 database-schema-designer 技能，为技能交换 App 设计后台数据库，引擎用 MySQL。
   ```

3. 一句话需求会用选择题追问最多 4 轮（只问会改变表结构的产品决定）；若你已提供详细 PRD，则只确认缺口。
4. 交付：`schema.sql`（MySQL 用 `schema.mysql.sql`）+ `database-design.md`（假设、关系、每表用途和索引）。

> 需要接本仓库的 `sql-to-*` 后端脚手架时，引擎选 **MySQL**——那些技能吃 MySQL `CREATE TABLE`，且不执行 DDL。

## 4. spec-kit（完整 SDD 流水线）

**主要支持**：DSH、Cursor、Claude Code、Copilot CLI 等 40+ Agent（通过 `specify init --integration <key>` 安装）。

Spec Kit 是 GitHub 官方开源工具包，走完整流水线：`constitution → specify → plan → tasks → implement → converge`。

以 **DSH** 为例（integration key 为 `dsh`）：

1. 先安装 CLI（需 Python 3.11+ 与 `uv`），然后初始化：

   ```bash
   specify init my-project --integration dsh
   ```

   已有项目用 `specify integration install dsh`。

2. 技能会装到 `.dsh/skills/speckit-<command>/SKILL.md`，在 DSH 对话中依次调用：

   ```text
   /speckit-constitution    # 项目原则
   /speckit-specify         # 根据需求生成规格
   /speckit-plan            # 实现计划
   /speckit-tasks           # 拆分任务
   /speckit-implement       # 执行实现
   /speckit-converge        # 检查收敛
   ```

   `implement` 与 `converge` 交替执行，直到报告 `Converged`。

3. 可选扩展：`specify extension add bug`（缺陷修复）、`add assess`（想法评估，输出 go / needs-clarification / kill）。

> Cursor 的用法相同，把 `--integration dsh` 换成 `--integration cursor-agent`，技能装到 `.cursor/skills/`，在 Cursor 对话中调用同名命令。

## 典型组合顺序

```text
it-requirement-analysis（业务需求 / PRD）
   → brainstorming（技术方案与设计规格）
   → database-schema-designer（数据库设计 + DDL）
   → spec-kit 或 sql-to-* 技能（规格驱动实现 / 生成后端脚手架）
```

如果只需要其中一步，单独使用对应技能即可；本仓库不负责技能测试，验证在独立项目中进行。
