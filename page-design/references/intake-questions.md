# 需求采集清单（Intake）

> 配套 SKILL.md 第 1 步。这份清单存在的唯一理由：**学生在动手前既看不出候选长什么样，也说不清自己要什么。**
>
> "要有效果""要设计感"这类句子不是需求，是情绪。直接照着做，等于让学生猜，也等于让你猜。

## 三条铁律

1. **一次问完** — 必问项 + 触发项合成**一条消息**发出，不逐轮挤牙膏。容许学生只答一部分，不允许你一次只问一件。
2. **描述不如指认** — 凡是视觉取舍，一律给**看得见的证据**（预览页 / 色卡 / 样式确认页），不用形容词代替。只给文字候选 = 违规。
3. **默认要摊开** — 学生没答的项你得替他定，但必须在确认回执里**显式标出哪些是你替他定的**，给他在动工前推翻的机会。偷偷用默认值，是返工的主要来源。

---

## 第一梯队：每次必问（6 项）

| # | 问什么 | 为什么必须问 | 不答怎么办 |
|---|---|---|---|
| 1 | 站名 / 一句话用途 / 主要给谁看 | 决定基调与信息密度；受众不同，同一行业的站会长得完全不同 | 从需求推断，回执里标出待确认 |
| 2 | **页面清单**（列出你的建议，让他增删） | skill 硬性要求：清单确认后才动手 | 用建议版作为默认，回执中说明可改 |
| 3 | 底色偏好：**白底 / 浅色 / 深色** | 这一条能一次性砍掉一半设计包，性价比最高的问题 | 默认白底（对外场景最稳） |
| 4 | 品牌主色 or **明确不要的颜色** | 颜色是"做完才发现不对"的头号返工项 | 用设计包默认色，回执说明可换 |
| 5 | **有没有参考**：见过的站、PV、截图、竞品 | 一张参考图胜过三段描述。有参照时几乎不会返工 | 无参照则必须走第 2 步可视化候选，不可跳过 |
| 6 | 内容是**你提供**还是**我用占位样例**；涉及资质/数据/证书时，用真还是假 | 涉伪造风险（虚假资质、冒充机构）；也影响"真实感"的写法 | 一律用明显虚构的占位样例并标注，**绝不伪造真实机构** |

> 第 6 项不是形式主义。学生说"展示资质"，你不知道他手上有没有真材料，就可能在页面上编出一张看起来很真的证书——那是实打实的风险。

---

## 第二梯队：触发式追问（听到这些词就停下来问）

学生在向你索要某种你还没见过的东西。**不要猜，问。** 每次触发都问同一组四件事：**位置 · 目的 · 参照 · 强度**。

| 触发词 | 追问（四件一组，一次问完） |
|---|---|
| **效果 / 动效 / 炫酷 / 震撼 / 高级感 / 有冲击力** | ① 出现在**哪里**（首屏 hero？产品区？整站滚动？）② 想**起到什么作用**（吸引停留 / 证明技术实力 / 展示流程）③ 有没有**参照**（某个站的某个地方）④ **强度**（一点点点缀 ←→ 满屏都要动），以及**不能接受什么**（怕不怕慢、花、晃眼） |
| **独特 / 有设计感 / 特别 / 不一样 / 有创意 / 别太普通** | ① 想让**哪个部分**特别（整体？某一个区块？某个元素？）② 想**传达什么**（可靠 / 前沿 / 人情味 / 反叛）③ 有没有**参照** ④ 什么是你**绝对不能接受**的（这条比"想要什么"更容易答，优先问） |
| **简洁 / 简单 / 干净 / 清爽** | 是指**信息少**（页面内容精简），还是**视觉干净**（内容多但排得克制）？两者做法完全不同 |
| **科技感 / 未来感 / 数字化** | 想要 **深色 + 霓虹** 那种，还是 **白底 + 数据可视化** 那种？给两种画面让他挑 |
| **复古 / 国潮 / 中式 / 古风** | 要的是**纹样与配色**，还是**排印方式**（竖排 / 印章 / 宣纸质感）？有无具体器物或作品参照 |
| **高大上 / 有档次 / 像大厂** | 具体**哪个公司/产品**的气质？以及"廉价感"在你心里具体是什么（土味渐变？弹窗？大段彩虹色？） |

> **永远优先问"不能接受什么"。** 学生往往说不清想要什么，但能立刻说出讨厌什么。负面清单比正面描述可靠得多。

## 视觉证据怎么给

SKILL.md 第 2 步要求做可视化候选，这里的执行细节：

1. **优先打开画廊。** 用 Glob 在工作区内找 `**/gallery/index.html`（本仓库为 `page-design-showcase/gallery/index.html`）。画廊是**同一套内容 × 9 种视觉**的对照，天然适合比选，且每张卡左上角有编号——让学生看完直接报号（"要 03"）。

   **要"打开"，不要"给路径"。** 把画廊作为可预览页面呈现给学生（present_files 或预览面板），而不是丢一句"文件在 xxx 目录，自己看"。给路径等于把找文件、开浏览器的负担转给学生，多数人不会去看，于是又回到"凭想象选"的老路。候选预览页同理。
2. **画廊不存在**时，逐个打开候选包的预览页（文件名稳定，可用 Glob 定位：`corporate-clean.html`、`flat-material.html` …），对应 SKILL.md 设计包一览表的"预览文件"列。
3. **两条路都不通**（无预览文件 / 无法展示）时，**必须先告诉学生"我现在没法给你看图"**，并把每个候选写成**可识别的具象特征**——写"深蓝实底 banner + 三栏产能数字"，不许写"稳重大气"。

**候选数量控制在 2–3 个。** 给 9 个让人选等于没选——除非你把画廊整个丢给他看，那是让他浏览，不是让他做决定。

## 色彩候选怎么给

**禁止甩三个等大色块。** 观感由**面积**决定，不由色值决定。同样三个色，谁占 60%、谁占 10%，出来是两个完全不同的网站。

正确做法（任选）：

- 按 **60 / 30 / 10** 的实际面积比例摆开，标出每块的角色（大面积底色 / 主结构 / 少量刺点）
- 或展示**该配色的实际渲染页面**（`palette-compare.html`、自定配色页）
- 或直接跳 R1.5：样式确认页

---

## R1.5：样式确认页（3 页以上的站点必做）

这是防止大规模返工的关键闸门。**先做一张单页，确认对了再做全站。**

一张 HTML，包含：

1. 三个色按实际比例的排布（不是等大色卡）
2. 一个 hero 区块（用真实文案）
3. 一组卡片 / 列表
4. 一组排版层级（h1–h3、正文、链接、按钮）

做完给学生看，问的就一个问题：**"这个方向对吗？"** 改这张页的成本是全站返工的几十分之一。

站点在 1–2 页、或学生明确说"你就按你的判断来"时，可跳过。跳过的判断要记进 README。

## 确认回执（动工前的最后一次确认）

把所有决策合成一张清单回传。**哪些是学生亲口定的、哪些是你替他默认的，必须分开标。**

```
已确认（你说的）：白底 · 7 页清单 · 深色系品牌色 #1565D8 · 资质用虚构占位
我替你定的（不同意就说）：
  - 设计包：flat-material（理由：你排除了深色底与老气风格，唯一贴合）
  - 动效：淡入 + 错开两种模式（skill 上限 2 种，"炫"由数据可视化承担）
  - 参考来实现"效果"：节点三级缩放 + 数字滚动
（以上 3 项任一被推翻，重走第 2 步，不直接改已经写好的页面）
```

这份回执要原文抄进 `doc/README.md` 的确认记录。**理由是：上下文重置后，接手的人能分清"用户的决定"和"上一次的默认"，不会把默认当成圣旨，也不会重新问一遍已经确认过的事。**
