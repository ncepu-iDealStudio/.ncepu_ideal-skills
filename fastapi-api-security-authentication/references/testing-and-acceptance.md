# 鉴权测试与验收

根据实际接口和本轮选定的权限策略，验证未授权访问、水平越权和垂直越权。须先满足[预检与门禁](preflight-and-gates.md)：没有合格令牌登录时，不要用 `Bearer test-token` 或直接签发令牌冒充「真实登录成功」。用户规则、证据推断及默认策略都可以作为测试契约，但须标明来源。测试需要有效的正向对照，不能仅凭登录成功、HTTP 200、接口清单或装饰器存在认定完成。

## 一、测试环境与数据

- 写入型测试默认只使用明确隔离的测试数据库和专用测试数据。测试及所有可能写入的 fixture/初始化入口，在首次建表、插入、修改、删除或清理前，通过**实际使用的连接或连接池**核对授权的实例地址、端口、库名与测试库所有权标识；不能只比对配置字符串或数据前缀。守卫失败必须在写入前停止，不可转为通过。
- 首次空库初始化例外：用户已明确授权初始化指定空库，且实际连接核验实例/库匹配并确认无表时，可以先建立本轮唯一归属标记；此后初始化、测试和清理均核验该标记。非空库缺标记或标记不符时不得补写标记冒认归属，也不得清空重建。
- 用户若明确指定并授权特定非独立库及写入范围，按该范围执行并说明差异；普通演示库不是默认授权。测试库不可用或权限不足时标记受阻，继续安全的只读或独立工作；不要搜索管理账号、擅自提升权限、清空或重建不属于本轮的库。
- 准备真实登录可用的高、低权限测试账号，以及同角色不同主体 A/B 和各自可证明归属的数据。只使用隔离数据；不输出密码、令牌、密钥、完整连接串或敏感响应。测试前记录必要状态；只清理由本轮创建、可确认的记录，并核验残留。MyISAM 等非事务表不能依赖回滚。
- 隔离守卫覆盖本轮运行的所有写入路径，包括沿用的 fixture、初始化和清理；只在新专项脚本检查、旧测试仅检查环境开关或配置字符串是不够的。必要时将同一守卫复用于这些入口，不能通过跳过守卫来跑旧测试。

## 二、必须验证的行为

选择能体现三项要求的代表性业务接口，包含一类有真实 A/B 归属的资源和一项管理员操作；明确每个测试对应的方法、路径、身份、对象和预期结果。无需补全所有业务 CRUD 测试；全部业务路由的保护接入核对与代表性动态测试是两项独立工作，实际未测试的范围应在报告中说明。

| 情形 | 正向和负向要求 |
| --- | --- |
| 公开白名单 | 登录等已确认公开接口无需已有令牌；其他受保护接口不能因路径相似、方法不同或漏挂鉴权被放行。 |
| 未授权访问 | 合法账号通过真实登录获得令牌并访问被允许接口；无令牌、伪造或过期令牌受到符合契约的拒绝，验证登录失败尝试限制。不得以直接签发令牌或 mock 冒充真实登录成功。 |
| 垂直越权 | 管理员可对同一有效接口与请求执行已授权操作，普通用户不能执行；分别断言真实响应和操作结果。使用既有组映射时，选取普通组作为对照，确认其不会因默认编号或示例配置变为管理员。 |
| 水平越权 | 同角色 A 可读取/修改自己的对象，A 对 B 的同类对象被拒绝；列表也不能返回 B 的未授权记录。创建和变更关联时检查归属。 |
| 字段权限 | 普通用户对本人允许修改的字段成功；提交角色、状态、归属等无权字段被拒绝或剔除，不能改变持久化值。创建与更新分别测试。 |
| 敏感输出 | 用合成口令哨兵覆盖字段校验错误及一个包含嵌套秘密的错误 body（如登录请求传数组），确认响应和捕获日志不回显；对选定账号资源的列表、详情（包括管理员响应）检查口令、哈希、恢复答案或恢复令牌等实际存在的秘密。若有受限内容，选一项验证无权者无法取得正文或播放/下载地址，不只检查口令已隐藏。断言只报告是否泄漏，不打印哨兵、令牌或整段响应。 |

写操作负例须使用有效路径和请求体，比较请求前后的**具体记录和相关字段**，确认没有发生修改、创建或删除；不能只比较总行数。若约定对无权对象返回 404，先证明对象存在且授权用户可以访问。不能仅以 404、405、422、500、超时或连接失败不等于 200 判断鉴权通过。

## 三、装饰器与回归

- 在实际应用中检查每个受保护业务接口使用 `middleware/` 中的鉴权装饰器，公开接口有明确例外；核对注册路由与方法，包括隐藏路由及非 `*Resource.py` 文件中的接口。在隔离应用中增加一条漏挂装饰器的非白名单路由，确认启动核对失败，或请求被拒且业务函数未执行；仅无令牌时 401、携带签名有效的令牌就放行，不算默认拒绝。
- 以真实 FastAPI 请求验证路由注册装饰器与鉴权装饰器的顺序、异步执行、参数依赖和原有异常处理；验证 401/403/约定的 404 以及允许访问的成功响应。OpenAPI、参数解析、业务响应和已授权的原 CRUD 应保持正常。仅有依赖注入、装饰器标记或语法检查不能证明拦截生效。
- 运行相关自动化测试，并在可用时用隔离测试账号启动实际服务、验证本机 HTTP 请求。区分内存替身、ASGI 请求、真实数据库和真实服务测试；失败要定位修复并复测，无法运行须明确报告，不得伪称通过。
- 本轮选中的原 CRUD 测试若使用 `Bearer test-token` 等假身份，改为真实登录与匹配权限的测试账号；保留合法业务成功断言。不得为了通过而把原成功断言全部改为 401/403、删掉或跳过。未运行的旧测试和原有占位 skip 单独列明，不要求补全无关的业务测试。
- 核对权限说明与实际装饰器角色、白名单一致；特别检查空角色集是否误把管理员也拒绝。OpenAPI 启用时检查 Bearer 安全方案及选定受保护操作的安全声明，公开登录不需预先认证。

## 四、可复跑的测试

- 将本轮代表性验证保存为项目测试，优先接入现有 pytest。若确需独立脚本，明确其执行命令与失败非零退出，不声称已由 pytest 收集；不能只在会话中跑一次临时脚本。
- 测试凭据路径、授权实例/库及归属标识从环境或本地配置提供，检查所需配置齐全后再连接。不可把个人绝对路径、本机服务器标识或某次实验库名固定为唯一运行条件，也不能取消实际连接核验来实现可移植性。
- 配置示例不含真实凭据；提供测试库初始化和必要迁移的运行说明。缺配置时明确跳过或受阻，并给出原因，不能计为通过。运行后核验清理；测试日志及 pytest 失败详情不得打印秘密或完整认证响应。

## 五、交付报告

简明列出：新增或修改的鉴权文件、白名单和角色/对象规则及其来源、初始化/启动/测试命令、已测试接口、正向与拒绝结果、被拒写入的数据核验、失败/跳过/受阻和清理情况。默认策略下管理员可用而普通用户受限的资源，与对所有角色暂时关闭的接口分别说明。所有请求一律拒绝不等于功能完成；只对真实正反证据覆盖的范围报告已验证，不把代表性测试描述为消除了整类安全漏洞。
