# 业务逻辑风险备忘录

本文件记录值得复用的风险模式，供盘点、设计权限和编写测试时参考。它不是漏洞清单、权限矩阵或自动扫描结果：先判断目标项目是否存在触发条件，再结合实际代码、数据约束和业务规则设计验证；不能因为字段或路由名称相似就认定存在漏洞，也不能把没有测试当作通过。对于不适用或不能安全验证的条目，报告具体理由及未覆盖范围。

本文所说的策略可以来自用户规则、项目证据推断或[默认策略](default-policy.md)，并非要求用户先提供完整业务说明。实际账号及历史对象的归属仍需可信关联，不能由策略假设伪造。

所有写入、异常注入和并发测试均遵守 [测试与验收规范](testing-and-acceptance.md)：默认使用独立专用测试库或不访问真实数据库的受控替身，先确认连接和权限，准备可清理的专用数据；不要对现有业务库执行破坏性测试。记录代码位置、数据约束、请求或输入条件、实际结果和判定；不要输出真实密码、令牌或个人数据。

按目标项目实际情况查阅相关条目，不必逐条生成报告。对实际发现的风险记录证据和测试结果；不能确定权限或完成测试时如实说明。数据库列不允许 NULL 也不能单独排除上游类型转换或令牌主体混淆。

## R01：认证主体的空值和字符串化混淆

- **触发条件**：登录时取得用户标识并放入令牌，后续再使用令牌中的标识查询主体；尤其要检查标识可空、不唯一、来源可变或会发生类型转换的情况。
- **风险**：例如 Python 的 `str(None)` 得到字符串 `"None"`；若存在另一个标识恰好为该字符串的账号，令牌可能解析为不同主体。数据库的 `NULL` 本身并不自动等于字符串 `"None"`，需要检查实际转换和查询链路。
- **检查**：从真实登录账号查找、主体标识生成、令牌签发、验签后回查到角色加载逐步追踪；核对标识是否非空、唯一、不可变，禁止因缺省值或类型转换切换主体。调查空字符串、重复标识、删除重建和标识复用。
- **隔离测试与证据**：构造两个不同权限主体，分别具有空标识与与转换结果相同的字符串标识；使用真实查询或明确说明替身范围，检查空标识账号不能签发可被解析为另一主体的令牌。再覆盖空字符串和重复标识；记录实际主体及拒绝结果，不只检查令牌生成成功。若环境无此触发条件，注明不适用依据。

## R02：部分更新中的显式空值绕过

- **触发条件**：更新 Schema 有可选的角色、状态、所有者或关联字段，服务使用 `exclude_unset` 一类方法只排除未提交字段。
- **风险**：显式提交 `null` 仍可能进入更新字典；如果仅在值不为 `None` 时检查权限，原有归属或敏感字段可能被清空。可空模型声明不代表真实数据库一定允许写入，须分别核对。
- **检查**：追踪请求解析、字段是否存在、权限检查、实际更新及数据库约束；核实非特权用户能否通过空值、空字符串或额外字段改变不允许修改的属性。
- **隔离测试与证据**：逐一列出实际存在的更新接口和权限敏感字段，对每个适用组合比较未提交、显式 `null`、空字符串、自身值和另一主体值，先证明允许修改的字段正常；禁止修改的字段无论返回拒绝还是被剔除，都须核对持久化前后相同，不能只看 HTTP 状态。一个账号字段的测试不能代表其他资源的归属字段也已覆盖。

## R03：非唯一业务键造成跨对象访问

- **触发条件**：对象权限或列表过滤依赖业务编号连接不同表，同时该编号可由低权限主体创建或修改，且数据库未保证其唯一或归属明确。
- **风险**：两个不同主体的对象使用相同业务键时，按该键过滤可能包含另一对象的关联记录；业务编号名称相同不证明关联和所有权正确。
- **检查**：核对实际数据库唯一约束、外键、软删除策略、创建/修改入口、关联查询及分页前过滤；确认作为权限依据的业务键是可信且无歧义的，而不仅检查用户 ID 唯一。
- **隔离测试与证据**：创建两个不同主体与各自关联记录，尝试重复或修改关联键；还应覆盖同一业务键对应有主记录与无主记录、空归属和软删除记录的组合，不能先过滤空归属再把剩余记录当作明确无歧义。验证碰撞被拒绝，或访问结果仍严格限定在授权对象；记录列表对象 ID、关联及数据状态，而非仅统计数量。

## R04：登录失败限流的遗漏与不一致

- **触发条件**：项目实现了登录失败计数、时间窗口或多进程限流。
- **风险**：不存在账号、锁定账号、未知口令格式等失败分支可能未计数；记录与检查使用不同窗口，并发先检查后计数也可能突破预期阈值。进程内计数不能自动等同于多实例全局限制。
- **检查**：核对所有失败路径、成功后的清除行为、实际配置、时间窗口、并发原子性和部署假设；不得因统一响应文案就认定限流正确。
- **隔离测试与证据**：用受控时钟、合成账号和隔离存储分别检查阈值、窗口过期、失败分支和并发行为，确认实际结果符合明确契约；标出仅单进程有效等限制。不要对共享服务发起压力测试。

## R05：不同口令入口的策略不一致

- **触发条件**：项目同时有注册、管理员创建/重置、本人改密、首次管理员初始化或其他口令设置入口。
- **风险**：某个入口只做哈希却跳过密码策略，或绕过哈希直接保存；一个入口测试通过不能代表其他入口正确。
- **检查**：列出全部实际入口，追踪输入校验、授权、哈希、落库和响应/日志；以本轮选定并说明来源的策略检查各入口的一致性。
- **隔离测试与证据**：对每个适用入口分别测试弱口令拒绝、合规口令可登录以及存储格式；测试数据仅用临时合成值。检查日志、响应和测试报告未暴露口令或其片段。

## R06：测试重复通过但数据未恢复

- **触发条件**：测试创建、修改或删除数据库数据，尤其共享种子或在 fixture `yield` 后才开始清理。
- **风险**：随机标识可能让多次运行都通过，却持续留下记录；若准备、断言或中断失败，恢复代码可能不执行。响应成功和测试全绿不能证明数据无变化。
- **检查**：确认每次创建后立即登记精确清理动作，修改前记录原值；分析 fixture 准备失败、断言失败与中断后的恢复路径。不能依靠宽泛前缀清理其他数据。
- **隔离测试与证据**：在专用测试库内比较运行前后本次对象及受影响状态；分别触发成功和受控失败，再检查清理结果。异常终止不能保证清理时列出准确残留与恢复步骤，不声称无残留。

## R07：通过修改关联将他人对象转到自己名下

- **触发条件**：低权限主体可更新资源的关联字段，且该字段决定权限范围，例如将记录从一个父对象关联到另一个父对象。
- **风险**：代码只判断请求中新的关联对象是否属于当前主体，却未判断被修改的原记录及其原关联是否可由当前主体操作；攻击者可能把他人的记录转到自己名下。单独检查新归属或检查创建操作不能证明更新操作安全。
- **检查**：追踪更新路径：先以服务端读取的原始记录验证当前主体对原资源的操作权限，再验证允许修改关联字段及新关联；还要处理未提交、显式 null、同值、无效值和歧义关联。判断应以已确认的业务规则为准。
- **隔离测试与证据**：在独立测试库或不访问真实数据库的受控替身中，构造主体 A、B 及各自对象；A 先能合法操作自己的记录，再尝试将 B 的记录改为关联到 A 的对象，断言被拒绝且 B 的记录和关联数据不变。另测合法主体可按规则修改自己的记录、以及向其他主体对象重绑定的情况。记录实际请求/身份/归属与前后状态；用替身时明确不能证明真实数据库写入行为。

## R08：文档隐藏误当作路由关闭或权限保护

- **触发条件**：项目按调试环境隐藏接口文档，或将接口设置为不出现在 OpenAPI；安全盘点仅依赖文档。
- **风险**：隐藏文档不等于路由未注册或需要认证。例如 FastAPI 的 `include_in_schema=False` 只影响 OpenAPI，接口仍可能被直接访问；隐藏接口也可能被授权清单遗漏。
- **检查**：对照各环境下的实际注册路由、真实响应和允许的身份，包含非 `*Resource.py` 文件中的接口；不以文档中不存在判断访问被禁止。区分“路由未启用”“需要认证”和“只是隐藏文档”；统一入口只验签不等于漏挂权限装饰器也会被拒绝。
- **隔离测试与证据**：在不连接真实数据库的独立 ASGI 应用或受控测试服务中，对调试关闭状态分别请求接口与 OpenAPI；如规则要求不可达或受保护，断言实际状态符合约定，并说明替身和实际运行环境的差异。不能用 OpenAPI 无该路径作为唯一证据。

## R09：不同操作入口的字段权限不一致

- **触发条件**：同一资源有创建、更新、状态变更或其他写入入口，或者不同请求 Schema 继承共同的字段定义。
- **风险**：某个入口限制了权限敏感字段，另一个入口仍允许客户端赋值；禁止额外字段并不能阻止已声明字段被滥用。余额、审核或认证标志等可作为排查线索，具体是否敏感、谁能修改仍须结合数据和业务证据确定。
- **检查**：逐个入口追踪实际请求 Schema、服务端默认值和落库赋值；比较各角色的允许、拒绝和待确认字段，包含继承字段及已声明但不该由客户端赋值的字段。未确认规则保守拒绝，不能因另一入口已检查就省略本入口。
- **隔离测试与证据**：按适用的入口和角色，以合法请求作正向对照，再分别提交无权字段，验证拒绝或剔除符合契约，且实际持久化值及归属未被改变；创建失败时检查没有产生记录，允许创建时检查服务端赋值。记录覆盖与未覆盖的入口、字段和数据库状态；不将受控替身结果称为真实数据库验证。

## R10：受限对象的正文和关联数据未继承访问规则

- **触发条件**：对象可能因状态、所有者、访问口令或其他规则限制读取，并且存在正文、列表摘要或评论、附件等关联内容。
- **风险**：只隐藏访问口令或限制对象详情，并不保证正文、列表、搜索、关联接口和分页计数不会泄露受限内容。关联对象的可见范围可能有独立规则，不能无条件假定与父对象相同。
- **检查**：依据明确业务规则分别检查对象和关联内容的读取条件，追踪详情、列表、搜索、嵌套响应及关联查询；核对状态、归属、访问组及付费/口令限制。不能只凭“已发布”放行，也不能只清空口令却仍返回受限正文或播放/下载地址。限制语义未决时保守拒绝相关普通用户访问，保留适用的管理入口并说明边界，不要求实现完整付费系统。
- **隔离测试与证据**：用合成受限对象和两名不同主体，验证有权者可访问、无权者不能取得不应见的正文或关联数据；同时检查详情、列表及适用的关联接口和计数。使用非空哨兵内容验证不会泄露，避免只检查口令字段或状态码；记录业务依据和替身/真实数据库的验证范围。

## R11：鉴权测试凭据文件被意外纳入版本控制

- **触发条件**：改造或测试产生本地环境文件、数据库客户端配置、临时脚本或其他包含密码、令牌或密钥的文件。
- **风险**：主 `.env` 被忽略不代表其他测试或临时文件也被忽略；仅添加忽略规则也不能移除已经被 Git 跟踪的文件。
- **检查**：列出本次创建的凭据文件路径，在 Git 仓库中分别核验忽略状态及是否已被跟踪，不读取或输出文件内容；同时确认示例文件只含非真实占位值。若不在 Git 仓库，明确记录无法验证 Git 状态，不把它当作已保护。
- **隔离测试与证据**：在临时仓库用不含真实秘密的示例文件验证忽略规则；对目标项目只检查文件路径的忽略和跟踪结果，不执行提交、历史重写或清理。发现已跟踪凭据或无法确认时停止将其纳入交付并报告，由用户决定如何处理历史和凭据轮换。

## R12：验证错误与业务响应回显凭据

- **触发条件**：登录请求使用长度、类型等 Schema 校验，异常处理器返回错误的 `input` 或记录完整请求；业务表包含账号密码、哈希、安全问题答案、恢复令牌或媒体访问口令等列。
- **风险**：正常登录响应不含口令，但 422 等错误响应和日志可能原样回显。错误定位到整个 body 时，敏感值可藏在数组或嵌套对象中，按错误字段名脱敏会漏掉；管理员权限也不意味着普通账号响应应带回认证或恢复秘密。
- **检查**：追踪参数校验、异常处理、日志及列表/详情 Schema，按字段用途识别敏感值，不只搜索 `password`。错误只保留安全的字段位置、错误类型和固定文案，不原样回传 `input` 或异常上下文；普通账号 CRUD 去除认证和恢复秘密，其他隐私或内容访问字段按明确业务权限处理。
- **隔离测试与证据**：用合成非空哨兵触发密码长度/类型错误，以及含嵌套秘密的非法 body（如登录接口收到数组），并读取包含恢复秘密的测试账号；断言响应和捕获日志不含相应秘密。只输出布尔判定和状态，断言失败也不输出完整响应或认证上下文；替身与真实服务证据分开报告。

## 新增条目

在维护本 Skill 且用户要求更新备忘录时，将新的、可复用的风险模式添加独立编号，并尽量保持每项四部分：**触发条件、风险、检查、隔离测试与证据**。记录可观察的失败机制和成立条件；如果证据来自静态分析或替身，明确其限制，不要把推断写成真实环境已受影响。优先补充已有条目的新边界，不为同一种机制反复新增条目；不要写入个人信息、真实凭据或针对某一次实验的路径。
