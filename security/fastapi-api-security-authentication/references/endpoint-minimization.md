# 接口面最小化与业务语义（通用）

脚手架会为每张表生成一整套 CRUD，但**鉴权加固不等于把这些接口原样交给管理员**。对安全敏感或没有业务动作的表，多余的创建/更新/删除接口会放大攻击面、绕过状态机、制造错误业务数据，甚至让审计记录可被篡改。

本文件不绑定具体表名，按**资源语义**给出默认处置，并要求先出「路由处置表」再实施。

## 一、核心原则

1. **每个保留的端点都必须对应一个真实业务动作**，并绑定明确权限码/对象规则；找不到调用方或业务含义的端点应删除。
2. **管理员不是全量 CRUD 的理由**。「只有管理员能调」降低不了误操作、越权和审计破坏风险。
3. **安全敏感记录优先只读或状态迁移**，不开放通用增删改。
4. **审计与历史记录不可变**：只能追加和查询，不能更新或删除。
5. **删除接口要成组处理**：路由、仅被它使用的 Schema/Service/Repository 方法与测试一起清理；共享代码保留。
6. **删除后必须对账**：实际注册路由与处置表一致，被删端点返回 404/405（不是 403），OpenAPI、README、权限说明同步更新。

## 二、按资源语义的默认处置

| 资源语义（按字段/用途识别） | 默认保留 | 默认删除或收窄 |
| --- | --- | --- |
| 账号/身份 | 列表、详情、创建、受控资料更新、状态/解锁、本人自助入口 | 硬删除账号（改用禁用/锁定/注销状态）；通用更新里改口令或角色；任意重置他人口令 |
| 会话/刷新记录 | 列表（本人或管理员按权限）、详情、登出/吊销等业务动作 | 管理员通用创建、通用更新、恢复已吊销会话 |
| 审计/登录尝试/决策日志 | 列表、详情（按权限，字段最小化） | 创建、更新、删除（审计只读） |
| 重置/验证令牌 | 申请、消费、作废等业务动作；最多返回元数据 | 通用 CRUD；读取或回显明文/摘要；手工创建或删除令牌 |
| 业务对象 | 按需求保留读写；状态/归属走专用接口 | 与业务无关的批量或纯脚手架 CRUD |
| 只读目录/字典 | 读取 | 写入 |
| 系统配置 | 按需求保留管理动作 | 无审计、无白名单的任意写接口 |

无法判断语义时，先按更小接口面处理并说明依据，不要默认保留全套 CRUD。

## 三、处置表（实施前必做）

逐条盘点实际注册路由，输出一份三方可见的处置表（可用 `scripts/check_endpoint_surface.py` 对账）：

```json
{
  "routes": [
    {"method": "GET", "path": "/api/v1/account/{id}", "action": "keep",
     "reason": "查看账号详情，权限码 account:read"},
    {"method": "DELETE", "path": "/api/v1/account/{id}", "action": "remove",
     "reason": "账号不做硬删除，改用状态禁用；无业务调用方"},
    {"method": "POST", "path": "/api/v1/session", "action": "remove",
     "reason": "会话由登录流程创建，管理端不应手工插入"},
    {"method": "DELETE", "path": "/api/v1/audit-log/{id}", "action": "remove",
     "reason": "审计记录不可删除"}
  ]
}
```

- `keep` 必须存在于最终实际路由；`remove` 必须不存在。
- 每条都要写理由；理由必须体现业务动作或删除原因，不能写「待定」。
- 需要改行为的端点（如把通用更新收窄为专用状态接口）按 `keep` 记录，并在理由里写明收窄内容。

## 四、实施顺序

1. 盘点路由 → 写处置表 → 对高风险删除项向用户确认（见第五节）。
2. 删除 `remove` 项：Resource 路由 → 仅被它使用的 Schema/Service/Repository 方法与测试。
3. 收窄 `keep` 项：去掉不应暴露的字段、合并到业务动作、补权限码/对象规则。
4. 重新导出 OpenAPI，更新 README 与权限说明中的接口清单。
5. 启动核对路由保护；运行处置对账脚本；请求被删端点确认 404/405。
6. 重跑鉴权与生命周期测试，确认删除没有破坏正常业务。

## 五、停问与确认

出现以下情况先问，不要直接删：

- 端点有外部/前端调用方，但仓库内看不到（可能影响线上契约）；
- 资源语义不明：既像审计又像业务数据；
- 用户要求保留某个看似多余的写接口（要求写明业务理由与权限边界）；
- 删除会牵连共享 Service/Repository 方法（需要拆分而不是整段删除）。

话术示例：

```text
检查结果：脚手架为若干安全敏感资源生成了完整 CRUD，其中以下端点没有业务动作或会破坏审计/会话语义（列出方法与路径）。
默认处置是删除这些端点，仅保留读取与受控业务动作。
删除可能影响现有调用方；请确认是否按处置表执行，或指出必须保留的端点及理由。请回复「确认删除」或给出保留清单。
```

## 六、反模式

- 把所有表都挂上「管理员专属 CRUD」当作完成鉴权；
- 允许管理员删除审计/登录尝试记录；
- 允许管理端手工创建会话或刷新记录；
- 允许通用更新接口修改口令、角色、归属、状态；
- 只删路由不删配套 Schema/Service 方法，留下可被再次挂载的死代码；
- 删除后不更新 OpenAPI/README，文档与实际接口不一致；
- 用 403 掩盖已删除的端点（应为 404/405）。
