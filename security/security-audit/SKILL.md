# 安全审计

凡是越过信任边界的输入，在校验之前都视为不可信。每条请求都在服务端核对「这个调用者能不能动这个对象」。能用参数化查询、自动转义、白名单时，不要在不安全的 API 外面再套一层黑名单。

本技能**只审计并给出修复方向**。它不替换本仓库的鉴权实现技能，也不提供攻击步骤、载荷或可直接利用的验证代码。

## 什么时候用

用：

- 用户要求安全审计、安全审查、上线前检查，或审查某个 PR / diff 的安全问题
- 正在写或改请求处理、认证、授权、文件、URL、HTML、SQL、命令、密钥、令牌、支付
- 用户丢来扫描器告警（SAST、依赖、密钥），要判断哪些是真问题

不用：

- 给已有 FastAPI 脚手架**补上**登录、Bearer JWT、角色或对象权限。那是 [fastapi-api-security-authentication](../fastapi-api-security-authentication/SKILL.md)。本技能若发现缺鉴权，写进报告后把实现交给那个技能
- 设计组织级安全制度、渗透第三方系统、或系统所有者没有授权的测试
- 只问某个 OWASP 名词的含义。直接解释，不要铺开全量审计

## 分工

| 用户要的结果 | 用哪个 |
| --- | --- |
| 这份代码有没有安全问题，问题在哪，该怎么改 | 本技能 |
| 把 FastAPI 脚手架收成「默认拒绝 + JWT + 对象权限」 | fastapi-api-security-authentication |
| 审计结论是 FastAPI 缺鉴权，且用户接着要求补上 | 先交本技能的报告，实现只走鉴权技能 |

`sql-to-fastapi-restfulapi-scaffold` 生成的 CRUD **默认没有登录**。审计这类项目时，把「业务路由未认证」记为发现，不要把它当成框架默认值就放过。本地演示且用户明确说不上线，严重性降为 note，并写明前提。

## 停下

出现下面任一条，停止扩大范围，只汇报并询问：

- 目标不是用户有权阅读和修改的代码或本地/测试环境
- 用户要求对线上或他人系统做动态攻击、绕过登录、伪造令牌
- 扫描器会把源码或结果上传到第三方。先问，同意后再跑
- 发现已提交的密钥、私钥、令牌。报告里只写类型和 `文件:行号`，不写值。告诉用户必须轮换。不要替用户轮换生产凭据，不要改写 git 历史来「消掉」泄露

## 工作步骤

1. **划定范围。** 确认目录、是否只看 diff、以及用户是否授权在本地跑只读扫描。列出入口：HTTP 处理函数、消息消费、CLI 参数、文件解析、webhook。标明调用者是匿名、登录用户、租户管理员还是内部服务。
2. **跑候选扫描。** 在目标项目根执行。命中是候选，不是结论。

```powershell
python "<skill目录>/scripts/scan_sinks.py" "<目标项目根>"
```

3. **沿数据流核对。** 不可信数据落到 SQL、命令、HTML、服务端请求的 URL、文件路径、反序列化、模板、重定向、日志时，必须有校验或安全 API。按适用类别阅读 [检查清单](references/checklist.md)。识别到本仓库的后端脚手架时，同时用 [技术栈落点](references/stack-map.md)。
4. **判定。** 每个候选三选一：确认发现、误报（写原因）、不适用。不要把扫描输出原样贴进发现表。
5. **修复方向写在报告里。** 换成安全 API（参数化查询、自动转义、白名单、服务端归属条件）。不要建议在字符串拼接的 SQL/命令/HTML 前面加正则过滤。用户要求动手改时：FastAPI 鉴权走另一个技能；其余修复只改确认的根因，并补一条回归测试（例如用户 A 访问用户 B 的资源被拒绝）。不写攻击脚本。
6. **按报告格式交付。** 见 [报告格式](references/report-format.md)。

仓库里已有的 `npm audit`、`pip-audit`、`govulncheck`、`mvn`/`gradle` 依赖检查可以跑。没有这些工具就在报告里说明未跑，不要为了审计去安装会上传代码的服务。

## 完成标准

三项同时成立才算审计做完：

- 范围内每个入口都标了「公开」或「需认证」，对象级检查落在服务端
- 候选扫描的每条命中都有判定；确认项有位置、影响、修复方向
- 密钥只出现类型和位置；需要轮换的已明确告诉用户

不能把「扫描器零输出」或「全员 403」当成完成。
