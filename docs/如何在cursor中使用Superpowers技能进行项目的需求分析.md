# 在 Cursor 中使用 Superpowers 做项目需求分析

> 给第一次用 Cursor 做需求的人。照着做完，你会从一句话想法，得到一份自己点过头的设计说明。这一课不写业务代码。
>
> 贯穿案例：**做一个技能交换的社交软件**。

---

## 先看差别：随便问，和按技能问

同一句话，两种问法，结果差很多。初学时先看懂这个差别，再往下做。

你对 Cursor 说：

```text
做一个技能交换的社交软件
```

**不使用技能时**，对话常常变成这样：

- 它马上选好技术，开始建登录页、列表页、数据库
- 问题要么不问，要么一次甩出十几个
- 顺手加上你没提过的功能：私信、积分、排行榜、支付
- 决定散落在很长的聊天记录里，关掉对话就不好找
- 想改范围时，页面和表已经写出来了

**使用 Superpowers 的 brainstorming 技能时**，同一句话会变成另一条路：

- 它先停下来，说明这是一个新项目，要先把设计说清楚
- 一次只问你一个问题，等你回答再问下一个
- 给出 2～3 种做法，并说明它推荐哪一种
- 设计分成几节，每一节等你说「可以」
- 最后写成一个文件：`docs/superpowers/specs/` 里的设计说明
- 你点头之前，不写页面、接口和数据库

用这个案例对照：

| | 随便问 | 使用技能 |
| --- | --- | --- |
| 你说完那句话之后 | 直接出代码和一堆页面 | 先问「第一版给谁用」 |
| 你要做的决定 | 混在一大段回复里 | 一次一个，答完再继续 |
| 积分、支付这类功能 | 经常被一起生成 | 要你点头才留下，没点头就删 |
| 做完需求时你手里有什么 | 一段聊记录 | 一份能打开核对的设计文档 |
| 接下来改范围 | 先改已经写好的代码 | 先改文档，再决定写不写代码 |

技能带来的好处就这几件：范围是你定的，每次只做一个决定，方案能比较，结果留在文件里，代码排在你同意之后。

下面的步骤就是在走右边这一列。

---

## 0. 做完这一课，你手里有什么

你先只有一句很短的想法。Superpowers 会把这件事问清楚，写成一份设计说明。

| 你来做 | 你会得到 |
| --- | --- |
| 说出想法 | 它先说明这是一个新项目，要先写设计 |
| 一次回答一个问题 | 2～3 个做法，以及它推荐哪一个 |
| 每一节设计回复「可以」 | 一份设计文档，路径在 `docs/superpowers/specs/` |

顺序是固定的：

```text
说明这是新项目
  → 一次只问一个问题
  → 给出 2～3 个方案，并推荐一个
  → 设计分节讲，每节等你点头
  → 写成设计文档，等你打开文件看
  → 你批准之后，才进入实现计划
```

你还没点头之前，项目里不应该出现页面、接口或数据库代码。

---

## 1. 开工前准备

| 要有 | 说明 |
| --- | --- |
| Cursor | 后面用的是 Agent 对话 |
| 一个空文件夹 | 专门放这个 App，例如 `D:\work\skill-swap` |
| Git | 设计文档写好后会提交这一份文件 |

用 Cursor 打开这个空文件夹。如果它还不是 Git 仓库，在终端执行：

```powershell
git init
```

---

## 2. 第 1 步：安装 Superpowers

1. 在 Cursor 里打开 **Agent** 对话。
2. 输入并发送：

   ```text
   /add-plugin superpowers
   ```

   也可以打开插件市场，搜索 `superpowers`，安装同名插件。

3. 安装完成后，**新开一轮 Agent 对话**。刚才那一轮对话不会自动带上刚装好的技能。

---

## 3. 第 2 步：确认已经装上

在新对话里发送：

```text
列出当前可用、和 Superpowers 相关的技能。
```

回答里应能看到 `brainstorming`。这一课用它来做需求分析。设计被你批准之后，下一步技能是 `writing-plans`，本课先用不到。

看不到这些名字时，关掉当前对话，再开一轮 Agent 对话，把上面那句再发一次。

---

## 4. 第 3 步：先记住这个软件要做成什么样

练习时按下面的范围回答。你自己的项目可以改这些句子；改了之后，第 7 节的核对清单也一起改。

**想法：**

> 做一个技能交换的社交软件。我会摄影、想学吉他，就找到一个会吉他、想学摄影的同学，我们互相教对方。

**这一版就定这几件事：**

| 决定 | 练习时这样答 |
| --- | --- |
| 谁来用 | 在校大学生，学校邮箱注册，一个邮箱一个账号 |
| 怎么交换 | 线下见面，各教对方一项，每次大约 1 小时 |
| 一条技能是什么 | 「我会的」和「我想学的」，各写一句话 |
| 怎样算完成 | 双方都按下「这次交换完成」，主页能看到完成次数 |
| 这一版不做 | 线上视频、支付、排行榜、作品集、积分 |

---

## 5. 第 4 步：开始做需求

### 5.1 把这段话发出去

新开一轮 Agent 对话，整段复制：

```text
请使用 brainstorming 技能，把下面这个想法做成设计说明。

想法：做一个技能交换的社交软件。
在校大学生用学校邮箱注册。我会摄影、想学吉他，就找到一个会吉他、想学摄影的同学，约线下见面，各教对方大约 1 小时。

【这一版已经确定】
- 用户：在校学生，学校邮箱，一个邮箱一个账号
- 技能卡片：我会的、我想学的，各一句话
- 交换：线下，每次约 1 小时，双方各教一项
- 完成：双方都确认后，完成次数加一
- 不做：线上视频、支付、排行榜、作品集、积分

【要求】
1. 这是一个还没有代码的新项目，请先把这个判断说出来；
2. 一次只问我一个问题，问完等我回答；
3. 给出 2 到 3 个方案，说明推荐哪一个、为什么；
4. 设计分节讲，每一节等我回复「可以」再写下一节；
5. 我批准之前不要写业务代码，不要建页面、接口或数据库；
6. 设计写入 docs/superpowers/specs/YYYY-MM-DD-skill-swap-design.md，写完告诉我文件路径，等我打开文件看过再继续。
```

### 5.2 第一段回复里应该有什么

- 它说明正在使用 `brainstorming`
- 它说明这是一个新项目，要先把设计写清楚
- 它只提出 **一个** 问题，然后停下

范围已经写在上面了。它若再问「是不是学校邮箱、是不是线下」，回复：

```text
对，按我上一条里「这一版已经确定」的范围。请继续下一个还没确定的问题。
```

它若一次抛出很多问题，回复：

```text
一次只问一个问题。问完等我回答。
```

它若直接创建页面或数据库，回复：

```text
先停。继续用 brainstorming。我批准设计文档之前不要写代码。
```

它若说「这个很简单，不用写文档」，回复：

```text
这是一个新项目，文件夹里还没有功能代码。请把设计写成 docs/superpowers/specs/ 下的文档。
```

### 5.3 问题对不上时，用这些回答

它问的原话每次会不一样。对上左边的话题，就发右边这一句。

| 它在问 | 你回复 |
| --- | --- |
| 还要不要做线上课、直播、视频 | `第一版只做线下，约 1 小时，双方各教一项。` |
| 要不要收费、积分、时间银行 | `第一版不收费，也不做积分。` |
| 技能要不要上传作品、证书 | `各用一句话说明。不上传作品集。` |
| 怎样算一次交换完成 | `双方都按下「这次交换完成」才算完成。主页显示完成次数。` |
| 谁可以注册 | `在校大学生，学校邮箱，一个邮箱一个账号。` |
| 两个人怎么找到彼此 | `先做双向匹配：我会的对上对方想学的。` |

### 5.4 在三个做法里选一个

问题问完后，它应给出 2～3 个做法，并推荐一个。这个例子里常见的三个方向是：

| 方案 | 做法 |
| --- | --- |
| A. 信息墙 | 发一条帖子，等人来联系 |
| B. 双向匹配 | 「我会的」对上对方「我想学的」，再发出邀约 |
| C. 时间银行 | 用积分结算每一次教学 |

你回复：

```text
选 B。第一版做双向匹配和线下邀约。不做积分，不做支付。
```

它只给一个方案时，回复：

```text
请给 2 到 3 个方案，并说明你推荐哪一个。
```

### 5.5 一节一节看完再点头

它会把设计分成几节。看完一节再回复。练习时按这个顺序确认：

1. **谁可以注册**：学校邮箱，一个邮箱一个账号。
2. **技能卡片**：我会的、我想学的，各一句话。
3. **匹配和邀约**：找出互相能教的两个人；一方发起邀约，另一方接受后才约日期和时间。
4. **完成**：双方都确认，完成次数加一。只剩一方确认时，停在「待对方确认」。
5. **这一版不做**：线上视频、支付、排行榜、作品集、积分。

某一节要改，就写明改哪里：

```text
这一节先不要地点，只约日期和时间。其余可以。
```

五节都同意之后，回复：

```text
可以。请把设计写成 docs/superpowers/specs/YYYY-MM-DD-skill-swap-design.md。写完告诉我路径。我先看文件，先不要写实现计划，也不要写代码。
```

它若提议打开浏览器做原型，回复：

```text
先不用浏览器，继续用文字把设计讲完。
```

---

## 6. 对话里会依次发生这些事

1. 说明这个新项目要先写设计
2. 看一眼当前文件夹（这时还是空的）
3. 一次一个问题，把还没定的点问完
4. 给出 2～3 个方案和推荐
5. 分节讲设计，每节停下等你说「可以」
6. 把设计写入 `docs/superpowers/specs/YYYY-MM-DD-skill-swap-design.md`
7. 检查文档里有没有「待定」「TODO」、前后矛盾、你没同意的功能
8. 把文件路径发给你，停下来等你看文件

日期是你做练习的当天。文件名里应能看出是技能交换，例如 `2026-11-20-skill-swap-design.md`。

中间如果跳去写代码，用第 5.2 节里「先停」那一句把它拉回来。

---

## 7. 第 5 步：打开设计文档核对

### 7.1 文件应该在这里

```text
skill-swap/
└── docs/
    └── superpowers/
        └── specs/
            └── YYYY-MM-DD-skill-swap-design.md
```

在 Cursor 左侧文件树里打开它。对话里说「写好了」，但左边没有这个文件，就回复：

```text
我在项目里没有找到 docs/superpowers/specs/ 下的设计文档。请把文件写出来，把完整路径发给我。
```

### 7.2 对照清单

- [ ] 用户是在校学生，学校邮箱，一个邮箱一个账号
- [ ] 技能卡片有「我会的」「我想学的」，各一句话
- [ ] 交换是线下，每次约 1 小时，双方各教一项
- [ ] 邀约要对方接受；时间至少有日期和时间
- [ ] 双方都确认才算完成；只有一方确认时是「待对方确认」
- [ ] 主页能看到完成次数
- [ ] 写明不做：线上视频、支付、排行榜、作品集、积分
- [ ] 没有「待定」「TODO」「以后再说」

### 7.3 文档里多了功能

```text
设计文档里的「积分」不在这一版里，请删掉。
改完再把文件路径发给我。先不要写实现计划。
```

把「积分」换成你看到的那个功能名。

清单都对上之后，回复：

```text
设计文档可以。需求分析到这里为止。
```

---

## 8. 到这里，需求分析就做完了

设计文档里应能直接读出：

- 用户是谁
- 一张技能卡片上有哪些字
- 两个人怎样找到彼此、怎样邀约
- 怎样算完成
- 哪些功能这一版不做

你没有让它继续时，它不应开始建表或写页面。

若要接着写实现计划，再发下面这段。那是下一步，本课不要求做完：

```text
设计文档已批准。请使用 writing-plans 技能，按 docs/superpowers/specs/ 里的那份设计写实现计划。
计划里不要加入视频、支付、排行榜、作品集和积分。
```

计划会写到 `docs/superpowers/plans/`。

---

## 9. 常见情况

### 9.1 它没有按这个流程走

提示词里要有 `请使用 brainstorming 技能`。然后新开一轮 Agent 对话，重新发送第 5.1 节的整段话。

### 9.2 它一上来就写代码

回复：

```text
先停。继续用 brainstorming。我批准设计文档之前不要写代码。
```

已经生成的页面、接口、数据库文件删掉，从第 5.1 节再来一次。文件夹里先只留 `.git`。

### 9.3 一次问了十个问题

回复：`一次只问一个问题。问完等我回答。`

### 9.4 方案只有一个

回复：`请给 2 到 3 个方案，并说明你推荐哪一个。`

### 9.5 设计里出现积分或支付

回复：`这不在第一版。请从对话和设计文档里去掉。`

### 9.6 说写好了，但没有文件

回复第 7.1 节那一句。

### 9.7 它要打开浏览器画界面

回复：`先不用浏览器，继续用文字把设计讲完。`

### 9.8 刚装完插件，当前对话没变化

新开一轮 Agent 对话，再发第 5.1 节的提示词。

---

## 一句话总结

```text
打开空文件夹 → 在 Agent 对话里安装 Superpowers → 新开对话
→ 发「技能交换」那段提示词 → 一次答一个问题
→ 选双向匹配 → 分节点头
→ 打开 docs/superpowers/specs/ 里的设计文档，逐条核对
```

你回复「设计文档可以」之后，这一课就做完了。
