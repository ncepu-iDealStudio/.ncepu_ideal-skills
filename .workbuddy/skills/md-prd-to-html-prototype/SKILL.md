# MD‑PRD转HTML交互原型 Skill

## 目标
读取用户指定的本地 `.md` 需求/PRD文档，解析：页面清单、角色、字段、按钮操作、弹窗、表格、筛选条件，生成**单个完整离线HTML原型文件**，所有CSS、JavaScript全部内联，无外部CDN以外依赖，保存到项目目录，直接浏览器打开评审。

> 重要约束
> 1. 不要生成多个零散HTML页面，默认输出**单文件HTML**；用户明确要求多页面再生成多文件。
> 2. 禁止脑补业务字段；md文档中信息不足，列出待确认清单，不要自行编造字段。
> 3. 原型定位：**需求评审低保真可交互原型**，不是最终上线产品；mock模拟交互，不需要后端真实接口。
> 4. UI风格：企业后台系统，简洁中性，侧边导航栏+主内容布局；表单、表格、弹窗、搜索筛选都要有基础JS模拟交互。

## 执行流程
### 阶段1：确认输入源
1. 请用户提供本地md文档文件名/相对路径，例如 `./prd/报修系统需求.md`
2. 读取该md全部内容。
3. 解析提取关键信息：
    - 系统名称、目标角色
    - 需要实现的页面列表（登录页、列表页、新增表单、编辑弹窗、详情页等）
    - 每个页面的字段：输入框、下拉、日期、表格列、按钮
    - 交互行为：新增、编辑、删除、查询筛选、弹窗弹出关闭、状态切换
    - 非功能约束：是否移动端优先，后台系统还是C端网站

> 如果md文档缺少页面、字段描述，输出待确认问题列表，不要强行生成原型。

### 阶段2：原型设计规则（强制遵守）
1. 使用Tailwind CSS CDN做样式，全部JS写在同一个html文件script标签内。
2. 内置mock模拟交互：
    - 侧边菜单切换不同页面视图（单文件内视图切换，不跳转新页面）
    - 表单点击新增弹出弹窗，关闭弹窗
    - 表格模拟筛选、重置按钮
    - 模拟提交成功提示toast消息
3. 使用模拟假数据填充表格，贴近业务场景。
4. HTML文件输出路径：和源md同目录，文件名 `原型‑{系统名称}.html`。

### 阶段3：输出产物
1. 将完整的HTML代码写入本地文件。
2. 输出摘要报告：
    - 原型文件路径
    - 已经实现的页面清单
    - 支持的模拟交互
    - ⚠️待确认/缺失的业务点（原型中未完善部分）

### 阶段4：迭代入口
告知用户：
> 原型已生成，你可以：
> 1. 修改源md需求文档，再次执行本skill，重新生成原型；
> 2. 告诉我需要调整页面、字段、交互，直接迭代更新html原型。

## 禁止行为
1. 不要输出markdown包裹的代码块就结束，**必须调用写文件指令写入本地html**。
2. 不要生成依赖本地css/js外部文件的原型，全部内联。
3. 不要做华丽高保真美工，保持适合需求评审的低保真业务原型。
4. 不生成真正业务逻辑，仅做前端模拟交互。
