# 输出目录与命名契约（output-contract）

本文件只回答一个问题：产物写到哪里、叫什么、目录与状态文件如何组织。
离线 HTML 结构与交互实现见 `interaction-contract.md`；端识别问题、澄清标记与状态文件内容模板见 `intake-and-state.md`。三者职责不交叉，按需读取。

## 1. 原型根目录

- 原型根目录由用户在步骤 1 明确指定，是一个已存在或可由技能创建的文件夹路径，技能不得自行假定默认值。
- 三端目录固定为该根目录下的一级子目录 `www/`、`admin/`、`app/`，不得改名、不得嵌套到二级、不得增加第四个端目录。
- 含义固定且与项目无关：`www/`＝前台门户，`admin/`＝后台管理，`app/`＝移动端。
- 每次调用只在一个端目录下产出文件：用户本次选中哪个端就只写哪个端；其余端保持原样或不存在，留待后续调用续写（分次续写）。
- 除三端目录与状态文件 `_原型说明.md` 外，不得在原型根目录创建其它文件或目录（以 `.` 开头的隐藏目录忽略）。

## 2. 目录树（两种模式的完整形态）

```
<用户指定的原型根目录>/
├── _原型说明.md                  # 跨调用状态载体，必有
├── www/                          # 前台：仅当生成过前台时存在
│   ├── index.html                # 单页模式：唯一主文件；多页模式：导航入口
│   └── pages/                    # 仅多页模式存在
│       └── <page-id>.html        # 每页一个 HTML
├── admin/                        # 后台：仅当生成过后台时存在
│   ├── index.html
│   └── pages/
└── app/                          # 移动端：仅当生成过移动端时存在
    ├── index.html
    └── pages/
```

- 某端从未生成过时，其目录不应出现；已生成过的端目录保留原有内容，续写不得删除或覆盖未涉及的页面。

## 3. 单页模式文件命名

- 该端目录下有且只有一个主文件 `index.html`，它包含该端全部视图。
- 视图之间用菜单/标签切换（同一个 HTML 内部切换显示），不产生第二个 HTML 文件。
- 单页模式不创建 `pages/` 子目录；若该端此前有多页产物，改动模式前须先向用户确认，不静默混用。

## 4. 多页模式文件命名

- 该端目录下必须有 `index.html` 作为导航入口，并存在 `pages/` 子目录。
- 每个页面一个独立 HTML 文件，路径为 `pages/<page-id>.html`。
- `<page-id>` 使用小写 kebab-case：仅小写字母、数字与连字符 `-`，单词间用 `-` 分隔，不含空格、中文、下划线或大写字母（例：`user-list.html`、`order-detail.html`）。
- 页面 id 在单个端内唯一；不同端可以出现同名页面文件，因为分处不同端目录。

## 5. index.html 与内部链接规则

- 多页模式的 `index.html` 必须链接到该端 `pages/` 下的全部页面，不遗漏、不指向不存在的页面。
- 所有本地 `href` 必须是相对路径并指向真实存在的 `.html` 文件；禁止断链、禁止指向目录、禁止指向外部 `http://`、`https://`、`//` 地址。
- 页内锚点可用 `#id`，锚点前缀的 `href` 不算页面跳转；`mailto:`、`javascript:` 仅用于功能按钮，不作为页面导航。
- 单页模式无跨页 `href` 要求，但菜单切换控件仍需在页面内实现（见 `interaction-contract.md`）。

## 6. `_原型说明.md` 七个必含小节

状态文件固定位于原型根目录、文件名固定为 `_原型说明.md`，必须依次包含以下七节（内容模板见 `intake-and-state.md`）：

1. 系统名称与一句话定位。
2. 目标角色清单。
3. 候选端与已生成端（含生成时间）。
4. 页面清单（按端分组，并逐端标注单页/多页模式）。
5. 数据字典与 Mock 数据约定（字段名、类型、示例值、状态枚举）。
6. 待确认业务点（`[NEEDS CLARIFICATION]` 汇总）。
7. 生成历史（每次调用一条：时间、端、模式、产出文件）。

## 7. 状态文件读写规则

- 生成前先检查 `_原型说明.md`：存在则完整读取并续写，不存在则按 `intake-and-state.md` 的模板新建。
- 状态文件只记录结论与历史，不替代用户确认：选端、选模式问题每次调用仍须重问（见 `intake-and-state.md`）。
- 每次成功生成后，在"生成历史"节追加一条记录，字段固定为：生成时间、本次端（`www`/`admin`/`app`）、模式（`single`/`multi`）、本次产出文件清单；只追加，不覆盖或删除既有历史。
- 同步更新"已生成端"、"页面清单"与"待确认业务点"三节，使其与本次产物一致；未改动的端信息原样保留。
- 校验器只读取状态文件判断是否存在及是否记录本次端/页面，不写入；写入由技能在步骤 5 完成。
