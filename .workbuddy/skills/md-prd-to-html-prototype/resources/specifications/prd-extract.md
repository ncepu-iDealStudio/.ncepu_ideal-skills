# 从 Markdown 需求里提取什么

先读完整篇 md，再决定能不能生成。只提取文档里写了的内容。

## 要提取的项

- 系统名称
- 角色
- 页面清单（列表、表单、详情、弹窗各自算一种界面）
- 每个页面的字段：输入框、下拉、日期、表格列、按钮
- 交互：新增、编辑、删除、筛选、重置、弹窗开关、状态切换
- 文档如果写了「后台 / 前台 / 移动端」，记下它。本技能默认做企业后台壳；文档明确是前台或移动端时，在摘要里说明仍用了后台壳，并列出因此没表达的布局

## 何时停下来问

下面任一缺失，就列出待确认问题并停止，不要生成 HTML：

- 没有页面清单，无法判断要做哪些界面
- 某个要做的页面没有字段或表格列
- 按钮写了「提交」「编辑」，但看不出提交后数据出现在哪一张表

问题一次列完，每条对应文档里缺的那一块。不要改问主键、配色或组件库。

## 可以继续、并写进摘要的情况

- 没有示例数据：用文档中的字段造几行假数据，状态值只用文档里出现过的词
- 没有角色说明：侧栏不做按角色隐藏，在摘要里注明
- 删除、导出、权限没有写：不做这些按钮，在摘要的待确认里写一句
