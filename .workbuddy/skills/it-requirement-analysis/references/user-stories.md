# 用户故事 & 验收标准模板

## 用户故事格式

### 标准格式
```
作为 [角色]，我想要 [行为]，以便于 [价值]。
```

### 示例
- 作为**系统管理员**，我想要**批量导入用户的功能**，以便于**快速完成新员工账号初始化**。
- 作为**普通用户**，我想要**查看我的订单历史**，以便于**了解之前的购买记录**。

## 验收标准格式 (Given-When-Then)

### 基本格式
```
**场景：[场景名称]**

- Given: [前提条件]
- When: [触发动作]
- Then: [预期结果]
```

### 示例

**场景1：正常登录**

- Given: 用户已注册且账号状态正常
- When: 用户输入正确的用户名和密码，点击登录按钮
- Then: 系统跳转至首页，显示登录成功提示

**场景2：密码错误**

- Given: 用户已注册且账号状态正常
- When: 用户输入错误的密码，点击登录按钮
- Then: 系统显示"密码错误"的错误提示，停留在登录页

**场景3：账号不存在**

- Given: 用户未注册
- When: 用户输入不存在的用户名，点击登录按钮
- Then: 系统显示"账号不存在"的错误提示

## 完整示例

### 功能：用户注册

| 故事ID | 用户故事 | 优先级 |
|:---|:---|:---|
| US01 | 作为**访客**，我想要**注册账号**，以便于**成为正式用户** | P0 |

#### 验收标准

| 场景 | Given | When | Then | 优先级 |
|:---|:---|:---|:---|:---|
| 正常注册 | 用户不在系统中 | 填写有效信息并提交 | 账号创建成功，发送验证邮件 | P0 |
| 用户名重复 | 用户名已存在 | 填写已存在的用户名 | 显示"用户名已存在"提示 | P0 |
| 邮箱格式错误 | 用户输入错误格式 | 填写错误格式邮箱 | 显示"邮箱格式不正确"提示 | P0 |
| 密码强度不足 | 用户输入弱密码 | 填写简单密码 | 显示密码强度不足提示 | P1 |
| 必填项缺失 | 某项必填字段为空 | 提交空表单 | 高亮缺失字段，提示必填 | P0 |

| 复杂度 | 故事点 | 示例 |
|:---|:---|:---|
| 简单 | 1 | 静态页面展示 |
| 一般 | 2 | 简单CRUD |

## INVEST 原则

好的用户故事应该遵循 INVEST 原则：

- **I**ndependent（独立的） - 尽量减少依赖
- **N**egotiable（可协商的） - 不是固定合同
- **V**aluable（有价值的） - 对用户有价值
- **E**stimable（可估算的） - 可以估算工作量
- **S**mall（小的） - 一个迭代内完成
- **T**estable（可测试的） - 有明确的验收标准
