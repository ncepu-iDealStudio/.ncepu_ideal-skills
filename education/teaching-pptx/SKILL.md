# 知识点 → 教学 PPTX

## 阶段一：只交提纲

1. 取得知识点名称。用户只给名称时直接起草，不强制追问：默认沿用用户语言，面向初学者，按 20 分钟、8–10 页估算，并标明这些假设。只有主题确实无法判断时才问一个聚焦的问题。
2. 在对话中给出受众、先修知识、课时，以及 2–3 条可观察的学习目标。列逐页表：页码、标题、本页要点、建议版式、课堂活动或预计用时。封面计入页数；各页用时合计应与课时相符。
3. 按知识点选择教学顺序，例如：问题导入 → 核心概念 → 例子或反例 → 随堂练习 → 讲评或小结。练习应检验学习目标，不能只复述定义。
4. 结束时请用户确认当前提纲或提出修改，可同时邀请指定输出路径。**本阶段不写课件或中间文件、不安装依赖、不运行出片脚本。** 即使初始请求写了“直接生成”，也必须先给提纲并等待下一轮明确确认。收到调整意见时先给修订提纲；含糊回复不视为确认。

## 阶段二：按已确认提纲生成 PPTX

1. 与已确认的页数、页序、目标及受众保持一致。若发现要改变知识范围、增删页面或调整教学顺序，先给修订提纲并重新确认。
2. 按 [README.md 的规格](README.md) 准备 UTF-8 JSON。每页突出一个重点，按内容选版式：一句核心结论用 `focus`，两项对照用 `compare`，演示过程用 `steps`，课堂任务用 `practice`，小结或并列要点用 `bullets`。不为追求变化而硬套版式。保持同级标题字号一致，投屏文字过长就重写，不截断、不逐页缩小字号。正文写给学生看；把讲解步骤、衔接语和练习参考答案放在演讲者备注，避免在练习页提前揭示答案。涉及事实、公式、代码或计算时核查内容，不编造出处。代码示例若未运行，不声称已运行。
3. 默认输出到当前用户工作区的 `教学课件/`，用户指定路径则使用指定路径。优先使用现有 Python 环境；缺 `python-pptx` 时说明依赖，只有在宿主允许且有必要授权时才安装。以技能目录定位 `scripts/build_pptx.py`，以工作区定位规格文件和成品；路径含空格时加引号。JSON 规格是临时输入，按宿主规则清理本次中间文件，不删除用户已有文件。
4. 运行脚本生成真正的 `.pptx`。脚本会重新读取生成内容并校验页数、标题和备注。输出文件已存在时不得覆盖，改用新文件名或让用户指定新路径。遇到工具不可用或构建失败时，报告原因与下一步，不能用 Markdown、HTML 或 JSON 冒充 PPTX。
5. 交付实际文件路径、页数，并说明验证范围。若有 PowerPoint/LibreOffice 或预览能力，抽查封面和各类实际使用的正文版式，检查字体、对比度、换行溢出和备注；未做视觉检查要明确说明。
