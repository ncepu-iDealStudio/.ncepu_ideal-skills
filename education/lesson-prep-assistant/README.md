# 备课辅助助手（lesson-prep-assistant）

面向**计算机专业教师**的备课技能：给一个知识点和教学目标，先出提纲让你把关，确认后生成一套学生能在 VSCode 里打开自学的 Markdown 教材包。

- 技能入口：[SKILL.md](SKILL.md)
- 原创技能，本仓库自研，可自由使用与改造。

## 它解决什么问题

备课写讲义时常见的痛点：

- 一上来就写全文，方向错了要全部返工
- 讲义写成 PPT 式的要点罗列，学生看不懂、没法自学
- 讲解缺逻辑主线，概念、历史、应用、实操混在一起
- 缺少可运行的示例代码和图解，学生只能干读

本技能用**两阶段门控**和**五段认知逻辑**把这两件事固定下来，并采用一套经完整教材验证的成熟做法：**用学生亲身经历的生活场景开场 + 第二人称叙事 + 术语即释 + 诚实标注来源**，以及把示例代码作为**论证链的一环**（动机 → 简化边界 → 运行 → 输出解读 → 接回原理），而不是讲义的附件。

**所有例子都从学生生活里来**是本技能优先级最高的内容约束：开篇、类比、示例代码输入、练习场景都用学生亲眼见过、亲手做过的东西（注册邮箱、手机号、聊天、购物、游戏、已学知识）；"工单、日志、订单"这类需要行业背景的场景一律不用。

## 核心设计

### 1. 两阶段，中间有硬门控

```text
教师输入知识点 + 教学目标
        ↓
阶段一：生成教学内容提纲（拆解知识点 + 五段要点 + 资源规划）
        ↓
⛔ 停下来，等教师审阅 / 修改 / 确认
        ↓
阶段二：生成讲义 md + 示例代码 + 配图 + 导航 README
```

未经确认不生成正文，这是技能的硬性要求。

### 2. 五段认知逻辑

每个知识点按学生"从零到会用"的顺序讲（五段是内在叙事顺序，小节标题按内容自拟，不硬贴通用标题）：

| 顺序 | 段落 | 回答的问题 |
| --- | --- | --- |
| 1 | 是什么 | 这东西大概是个啥？ |
| 2 | 为什么会出现 | 没有它之前有什么痛点？ |
| 3 | 发展历程 | 为什么长成现在这样？ |
| 4 | 应用现状 | 现在用在哪、值不值得学？ |
| 5 | 如何开始使用 | 读完能不能马上动手？ |

### 3. 所有例子都贴近学生生活

选场景的标准只有一句：**学生亲眼见过、亲手做过吗？** 答不上来就换。优先用注册账号、登录验证、聊天消息、网购、游戏、校园生活、之前学过的知识；不用工单系统、日志分析、订单流水、ERP、运维告警这类行业场景。这条约束覆盖开篇、类比、示例代码的输入数据、练习背景和配图示意，而且从阶段一写提纲时就要逐项圈定。

### 4. 代码是论证链的一环

讲义里的示例按四环节写：先用具体场景给动机 → 声明简化边界（"它省略了什么"）→ 给运行命令和真实输出 → 逐句解读并把结论接回前面的原理。练习绑定具体示例文件并给验收条件；引用外部资料、图或未复跑的示例都标注来源与验证状态。

### 5. 产物是可自学的材料包

按规模选布局：少量知识点用平铺（`notes/` + `examples/` + `exercises/` + `assets/`）；多章节大课程用分章（每章自带讲义、示例、练习、图片，"搬一章不散架"）。

成品是**教材**而非幻灯片：充分展开、通俗易懂、示例可跑、关键处有图解。配图用 Mermaid 起草后导出 PNG 并保留 `.mmd` 源码（不同编辑器内嵌渲染差异大）。用 VSCode 打开根目录即可自学。

### 6. 先骨架后裁剪，保证系统性

只给一个宽泛主题（如"Python 网络编程"）时，技能不会直接拍平成一串知识点，而是要求：

1. **先列标准知识骨架**（模块 → 知识点），来源写明（教材目录 / 课程大纲 / 官方文档 / RFC）；
2. **再按课时裁剪**，用课时预算表逐项标注"讲 / 不讲 + 原因 + 分钟数"；
3. **交付前做完整性自检**：核心模块是否都有着落、有没有"枯燥但基础"的内容被悄悄漏掉、课时是否对得上、先修/后继衔接是否清楚。

配套在提纲模板里新增了**知识骨架表、课时预算表、课程衔接字段**，并把"因为不好演示就省略基础点"列为明确的反面模式。这样既保留"贴近学生生活"的可读性，又不牺牲课程完整。

## 如何使用

1. 在支持 Agent Skills 的工具中加载本技能（本仓库中位于 `.codebuddy/skills/lesson-prep-assistant/`，拷到目标工具的技能目录即可），或直接把 `SKILL.md` 交给 AI 阅读后按其流程执行。
2. 告诉 AI：要讲的知识点、教学目标、**课时（几分钟 / 几次课）**，以及学生基础/篇幅/技术栈/课程衔接（后四项可省，AI 会先问或给出假设）。**如果是宽泛主题，最好直接给出你认可的分节提纲**，AI 会据此列知识骨架再裁剪。
3. 收到提纲后重点审阅三处：**知识骨架有没有漏、课时预算合不合理、先修/后继是否衔接得上**；提出修改意见或明确确认。
4. 确认后 AI 生成完整材料包，告诉你在哪个目录，用 VSCode 打开即可。

示例输入：

> 给计算机专业大二学生讲"快速排序"，目标是能自己写出代码并分析复杂度，用 Python，课时 45 分钟。

> 给大二学生讲"Python 网络编程"，90 分钟两节课，按"网络基础 → 协议简介 → UDP → TCP → 项目"来组织。

## 文件结构

```text
lesson-prep-assistant/
├── SKILL.md                              # 技能入口：概述 + 两阶段工作流 + 完整性自检 + 风格要求
├── README.md                             # 本导读
└── references/
    ├── workflow-and-structure.md         # 输入澄清、骨架优先与课时裁剪、平铺/分章布局、导航 README 八块规范
    ├── cognitive-sequence-guide.md       # 五段认知逻辑 + 四条基调 + 写作技巧 + 贴近生活不牺牲系统性
    ├── templates.md                      # 提纲（知识骨架/课时预算/课程衔接）/ 讲义 / 示例说明 / 练习汇总
    ├── assets-guide.md                   # 代码四环节与练习验收、配图导出与来源标注
    └── worked-example.md                 # 完整讲义节选范文（生成时的具体参照）
```
