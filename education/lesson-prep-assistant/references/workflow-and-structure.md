# 工作流细节与产物结构

## 阶段一的输入澄清清单

教师输入往往不完整。按优先级判断哪些必须问、哪些可合理默认：

| 信息项 | 是否必问 | 缺失时的处理 |
| --- | --- | --- |
| 知识点范围 | 必问 | 无法推断，明确询问要讲哪几个知识点 |
| 教学目标 | 必问 | 无目标则无法裁剪深度，询问"学完要能做什么" |
| 学生基础 / 先修 | 建议问 | 默认按计算机专业大二、掌握一门编程语言处理，并在提纲中注明此假设 |
| 篇幅 / 课时 | 建议问 | 默认每个知识点一篇讲义、2000～3500 字，并在提纲中注明 |
| 语言 / 技术栈 | 建议问 | 默认 Python + 中文讲解，并在提纲中注明 |
| 是否有现成课件 / 示例材料包 | 可选 | 若有，请教师提供：改写或沿用其风格，而非另起炉灶 |

一次最多问 3 个最关键的问题；其余用合理默认并在提纲开头写明「本提纲的假设」，让教师一次性校正。

## 阶段一的拆解原则

- **粒度**：一个知识点 = 一个能独立讲清、可单独成文的概念/技术（如"快速排序""TCP 三次握手""Transformer 自注意力"）。太大就再拆，太小就合并。
- **顺序**：按依赖排序——先修概念在前，应用类知识点在后；在提纲里用一句话说明为什么这样排。大课程还要在开头放一张"全局链路图"，说明本章在整条链上的位置。
- **五段规划**：每个知识点都要为五段各写 1～3 条要点，并**拟定有信息量的小节标题**。宁可提纲细一点，也别让阶段二跑偏。
- **资源规划**：示例代码写清"这段代码演示什么现象/验证什么结论"；配图写清"这张图说明什么原理/流程"；来源写清哪些是外部资料、哪些示例可复跑。

## 阶段二的执行顺序

1. 先写 `README.md` 的框架（教学设计、全局图、学习路径、文件清单），确定全局结构。
2. 逐个知识点写讲义，边写边埋好对示例代码、配图、练习的相对链接；按 `cognitive-sequence-guide.md` 的四条基调（问题开场、第二人称、术语即释、诚实标注）写。
3. 按讲义中的引用，逐个补 `examples/` 与 `assets/`（或章 `images/`）；代码按 `assets-guide.md` 的四环节写，图按"Mermaid 起草 → 导出 PNG → 保留 .mmd"处理。
4. 补 `exercises/README.md` 练习汇总（模板四），回填讲义与章 README 的链接。
5. 回填根目录 README 的具体链接、图清单、学习路径与快速路径。
6. 写 `outline.md`（把确认后的提纲原样存档，便于以后修订时对照）。
7. 逐项自检（见 SKILL.md「常见错误」与各 reference 的自检清单）。

## 落点确认

生成前必须先确定材料包写到哪里：

- 教师指定了路径 → 用指定路径
- 未指定 → 在教师当前工作目录下建 `<课程主题>-教学材料/`，并在动手前一句话说明将写到此位置

**绝不**把生成物写进本技能目录 `education/lesson-prep-assistant/`，避免污染技能本体。

## 布局选择：平铺还是分章

按课程规模在阶段一确定，并写进提纲：

| 规模 | 布局 | 目录形态 | 适合 |
| --- | --- | --- | --- |
| 少量知识点（1～3 篇） | 平铺 | 材料包下 `notes/`、`examples/`、`assets/`、`exercises/` | 单主题备课、一次作业 |
| 多章节大课程（4 篇以上，或每章有多份代码/图/练习） | 分章 | 材料包下 `01-<章>/`、`02-<章>/`……每章自带讲义、`examples/`、`exercises/`、`images/` | 系列课程、整门课自学材料 |

分章布局示例：

```text
<课程主题>-教学材料/
├── README.md                    # 总入口：全局链路 + 各章导航
├── outline.md                   # 已确认提纲存档
├── 01-第一章/
│   ├── README.md                # 章导航（见下节规范）
│   ├── 01-知识点A.md
│   ├── 02-知识点B.md
│   ├── examples/*.py
│   ├── exercises/README.md
│   └── images/*.png + *.mmd
└── 02-第二章/
    └── ...
```

分章时每章自带资源目录，好处是"搬走一章不散架"；讲义引用用同级相对路径（如 `examples/xxx.py`、`images/fig1.png`），跨章引用用 `../02-第二章/...`。

## 导航 README 规范

材料包根目录与分章布局的章 README，都要写得像"导览"，至少覆盖以下八块（可按需合并）：

1. **一句话简介**：这门材料 / 这一章讲什么、适合谁，读完全程约多久。
2. **为什么按这个顺序读**：讲清章节依赖与设计意图——为什么先讲历史再拆机器、为什么环境配置放最后。这是全篇最有"老师味"的一段，不要省。
3. **先看一眼全局**：一张全局链路图 + 一句话说明"本材料只讲其中哪几层，其余章节如何归位"。没有全局图时，用一段文字描述整条链。
4. **各节各自回答什么问题**：表格列出"小节 / 文档 / 这一节回答 / 配套代码"，让学生按需跳读。
5. **配图与外部资料清单**：表格列出图号、文件、出现位置、讲什么、原始页面；说明外部图已本地化、断网可看；说明自绘图保留了 `.mmd` 源码。
6. **学完你应该能**：3～4 条可检验的能力描述，用"能对同学讲清……""能解释……并知道……"这种句式。
7. **运行前提与快速路径**：依赖与命令；再加一条"如果你只有二十分钟"的跳读路线，标出可跳过的段落。
8. **常见卡点**：列 1～2 个最高频报错及排错文档链接；结尾指向 `exercises/README.md`。

示例（章 README 骨架）：

````markdown
# 第 [N] 章 · [章标题]

[一句话简介。全程约 X 小时。]

## 为什么按这个顺序读

[2～3 段，讲清本章各节的依赖与设计意图。]

## 先看一眼全局：[链路名]

![全局图](images/00-pipeline.png)

> [一句话导览图解读 + 本章在整条链上的位置。]

## 各节各自回答什么问题

| 小节 | 文档 | 这一节回答 | 配套代码 |
| --- | --- | --- | --- |
| [N.1] | [链接] | [问题] | `examples/xxx.py` |

## 本章的配图与外部资料

[图清单表格 + 本地化说明 + 自绘图源码说明。]

## 学完这一章，你应该能

- [可检验能力 1]
- [可检验能力 2]

## 运行前提

[依赖与命令。]

## 如果你只有二十分钟

[跳读路线：读哪几节、跳过什么、之后再回来补什么。]

## 常见卡点

[高频报错 + 排错文档链接。]

练习汇总在 [exercises/README.md](exercises/README.md)。
````

## 增量修改已有材料包

教师可能要求"在第 3 篇后再加一篇"或"把某篇讲深一点"：

- 只改动相关文件，保持其余文件与链接不变
- 新增知识点时，同步更新总 README、章 README 的学习路径与 `outline.md` 存档
- 新增图时同步更新"`配图与外部资料`清单"
- 修改后重新检查受影响的相对链接
