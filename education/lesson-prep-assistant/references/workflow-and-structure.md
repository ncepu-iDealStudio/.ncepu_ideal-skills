# 工作流细节与产物结构

## 阶段一的输入澄清清单

教师输入往往不完整。按优先级判断哪些必须问、哪些可合理默认：

| 信息项 | 是否必问 | 缺失时的处理 |
| --- | --- | --- |
| 知识点范围 | 必问 | 无法推断，明确询问要讲哪几个知识点 |
| 教学目标 | 必问 | 无目标则无法裁剪深度，询问"学完要能做什么" |
| 学生基础 / 先修 | 建议问 | 默认按计算机专业大二、掌握一门编程语言处理，并在提纲中注明此假设 |
| 篇幅 / 课时 | 建议问 | 默认每个知识点一篇讲义、2000～3500 字，并在提纲中注明 |
| 语言 / 技术栈 | 建议问 | 默认 Python + 中文讲解，并在提纲中注明 |
| 是否有现成课件 | 可选 | 若有，请教师提供，改写而非另起炉灶 |

一次最多问 3 个最关键的问题；其余用合理默认并在提纲开头写明「本提纲的假设」，让教师一次性校正。

## 阶段一的拆解原则

- **粒度**：一个知识点 = 一个能独立讲清、可单独成文的概念/技术（如"快速排序""TCP 三次握手""Transformer 自注意力"）。太大就再拆，太小就合并。
- **顺序**：按依赖排序——先修概念在前，应用类知识点在后；在提纲里用一句话说明为什么这样排。
- **五段规划**：每个 knowledge point 都要为五段各写 1～3 条要点，宁可提纲细一点，也别让阶段二跑偏。
- **资源规划**：示例代码写清"这段代码演示什么现象/验证什么结论"；配图写清"这张图说明什么原理/流程"。

## 阶段二的执行顺序

1. 先写 `README.md` 的框架（学习路径 + 文件清单），确定全局结构。
2. 逐个知识点写 `notes/NN-<知识点>.md`，边写边在讲义中埋好对示例代码和配图的相对链接。
3. 按讲义中的引用，逐个补 `examples/NN-<示例名>/` 与 `assets/`。
4. 回填 README 的具体链接与说明。
5. 写 `outline.md`（把确认后的提纲原样存档，便于以后修订时对照）。
6. 逐项自检（见 SKILL.md「常见错误」）。

## 落点确认

生成前必须先确定材料包写到哪里：

- 教师指定了路径 → 用指定路径
- 未指定 → 在教师当前工作目录下建 `<课程主题>-教学材料/`，并在动手前一句话说明将写到此位置

**绝不**把生成物写进本技能目录 `education/lesson-prep-assistant/`，避免污染技能本体。

## 导航 README 规范

材料包根目录的 `README.md` 至少包含四块：

1. **一句话简介**：这门材料讲什么、适合谁。
2. **学习路径**：一个有序列表，按依赖顺序链接到各篇讲义，并标注每篇的大致阅读/实操时间。
3. **文件清单**：`notes/`、`examples/`、`assets/` 各目录的用途说明。
4. **如何使用**：用 VSCode 打开本目录 → 从 README 点进第一篇 → 安装 Mermaid 预览插件以看图 → 按顺序运行示例代码。

示例：

```markdown
# 计算机网络·传输层自学材料

面向计算机专业二年级学生，讲清 TCP 可靠传输的核心机制。全程约 3 小时。

## 学习路径

1. [01 TCP 是什么](notes/01-TCP是什么.md)（约 20 分钟）
2. [02 为什么需要三次握手](notes/02-三次握手.md)（约 30 分钟 + 实操）
3. ...

## 目录说明

- `notes/` — 讲义正文，一个知识点一篇
- `examples/` — 可运行示例代码，含运行说明与思考题
- `assets/` — 配图与素材

## 如何使用

用 VSCode 打开本目录，从上面的学习路径依次阅读。建议安装 Markdown Preview Mermaid Support 插件以显示配图。示例代码在各示例目录的 README 中说明运行环境与预期输出。
```

## 增量修改已有材料包

教师可能要求"在第 3 篇后再加一篇"或"把某篇讲深一点"：

- 只改动相关文件，保持其余文件与链接不变
- 新增知识点时，同步更新 `README.md` 学习路径与 `outline.md` 存档
- 修改后重新检查受影响的相对链接
