## 节选一：问题式开篇（对应"是什么"）

> 原文来自一篇讲 Transformer / Token / 注意力的讲义。注意它不先给定义，而是先抛一个学生自己也好奇的问题。

### 1. 一个代词引出的难题

先把这句英文翻译成中文：

> The animal didn't cross the street because **it** was too tired.

`it` 指谁？几乎所有人都会说：指那只动物。可如果换成：

> The animal didn't cross the street because **it** was too narrow.

同样一个 `it`，这次指的是街道。两个句子里，`it` 的位置一样、词形一样，决定它含义的，是**远处另一个词**——`tired` 还是 `narrow`。

人读这句话时，眼睛虽然一行行扫过去，脑子却会不停往回看：读到 `tired`，自动把它和 `animal` 挂上钩。机器要读懂这句话，也得有类似的动作。这个「往回看、并且知道该看谁」的动作，就是**注意力（attention）**。它是上一节里那次转折的核心，也是这一节要讲的第一件事。

## 节选二：痛点铺垫（对应"为什么会出现"）

> 注意：先讲清"没有它之前有什么麻烦"，再讲它是什么；用"忘性""慢"这种具象词，不堆术语。

### 2. 在 Transformer 之前：一个字一个字地读

2017 年之前，处理文本的主流网络是循环神经网络（RNN）及其改进版 LSTM、GRU。

它们的读法很像人逐字读书：读第一个词，得到一个「记忆状态」；把记忆状态和第二个词一起读，更新记忆；再读第三个……直到句末，最后那个状态就代表了整句话。做翻译时，再用这个状态一个字一个字地往外写。

这个设计很自然，但有两个躲不开的毛病。

第一是**忘性**。信息要沿着这条链一路传下去，传得越远越淡。读到一个 50 个词的长句，开头那个词的信息可能已经所剩无几。LSTM 用「门」来控制记什么、忘什么，缓解了这个问题，但没有根治。

第二是**慢**。第 5 个词必须等第 4 个词算完才能开始，整句话只能串行处理。这在 2012 年之后变成了要命的瓶颈：深度学习这条路的经验是「数据越多、模型越大，效果越好」，可串行结构让 GPU 的大规模并行能力用不上——你有一万个核心，也只能一个一个词地排队。

要「把模型做大」，先得把这堵墙拆了。

### 6. 动手一：只看前一个字的生成器，会绕圈

理解了原理，就能写一个极小的版本。下面这个程序只学一件事：**每个字后面最常跟哪个字**。它比真实模型简陋得多——真实模型看的是整段上下文，它只看前一个字——但足以让你亲眼看到「逐 token 生成」是怎么回事。

```python
"""字符级 bigram 生成：只学「前一个字 → 下一个字」，看看会发生什么。"""
import random
from collections import Counter, defaultdict

CORPUS = [
    "从前有座山，山里有座庙，庙里有个老和尚，老和尚在讲故事。",
    "老和尚讲的故事是：从前有座山，山里有座庙，庙里有个老和尚。",
]


def build_table(corpus):
    """统计每个字后面都跟过哪些字、各几次。"""
    table = defaultdict(Counter)
    for line in corpus:
        for a, b in zip(line, line[1:]):
            table[a][b] += 1
    return table


def pick_next(table, ch, rng):
    """按出现次数加权，抽一个下一个字。"""
    candidates = table.get(ch)
    if not candidates:
        return None
    chars = list(candidates)
    weights = [candidates[c] for c in chars]
    return rng.choices(chars, weights=weights, k=1)[0]


def main():
    table = build_table(CORPUS)
    print("以「庙」为前缀时的候选：", dict(table["庙"]))
    print("以「老」为前缀时的候选：", dict(table["老"]))

    rng = random.Random(7)
    text = "从"
    for _ in range(40):
        nxt = pick_next(table, text[-1], rng)
        if nxt is None:
            break
        text += nxt

    print("\n从「从」开始生成 40 个字：")
    print(text)
    print("\n它只盯着前一个字，不知道整段在讲什么——")
    print("所以很容易绕回「从前有座山」，或者在半句话中间突然停住。")


if __name__ == "__main__":
    main()
```

```bash
python chapters/01-llm-fundamentals/examples/next_token_demo.py
```

运行后你会看到两件事：一是候选表，`庙` 后面可能跟 `，` 也可能跟 `里`，各两次；二是生成结果——它大概率会绕回「从前有座山」，或者在一句话中间接不下去。原因很直白：**它只看得见前一个字。** 真实模型看的是整段上下文，还会记住「刚才在讲和尚」，所以不会这么早迷路。

这也顺带解释了为什么需要注意力：如果每个字都能回头看整句，「庙」后面该跟什么，就能由「前面是不是刚说过『有座』」决定，而不是靠一个字猜。

### 8. 动手练习

**基础练习**：把 `CORPUS` 里加上一句「庙门口有棵大树」，重跑 `next_token_demo.py`，观察 `庙` 的候选表变化。验收条件：能解释为什么候选里多了一个「门」，以及为什么生成结果可能因此走上另一条路。

**进阶练习**：把 `pick_next()` 里的加权抽样改成「永远选次数最多的那个」，再跑一次。验收条件：说明生成结果为什么更容易陷入循环，并对应到本节前面讲的「永远只挑最高分」与「按概率抽样」的区别。

**挑战练习（可选）**：修改 `tiny_attention.py`，把查询词换成 `street`，观察权重分布变化；再手工构造一组向量，让 `it` 更关注 `street`（对应 `because it was too narrow` 那句）。验收条件：权重最高项变成 `street`，并能说明你改了哪个向量的哪个维度。

### 10. 这一节带走了什么

一台大模型的核心，可以压缩成一句话：**把文本切成 token，用 Transformer 的注意力让每个 token 交换信息，然后逐个预测下一个 token。** 训练时并行地做这道填空题，推理时串行地生成；温度决定它多保守，KV cache 决定它多快。

这套机制解释了它为什么强（要猜得准，就得把语言里的知识压进参数），也预告了它为什么弱（目标是「像」，不是「对」）。下一节就把这些弱点一条条摊开。
