# TeachAnyHE：高等教育互动课件执行摘要

TeachAnyHE 的目标不是把知识堆进页面，而是把大学课程的一节（或一个专题）做成**有问题锚点、有推导/仿真/证明、有讲解、有评估、有知识体系映射**的学习体验。它沿袭 TeachAny 的「学习闭环优先」内核，但把面向对象从中小学生换成大学生/研究生，把「学段-学科-单元」换成「专业-课程-章节-知识点」，把「课标挂树」换成「培养方案/教学大纲/OBE 目标映射」。

主文件只保留决策骨架；细节按需读取卫星文档。

## 何时使用

使用本技能：

- 用户要制作、改造、调试高等教育课程的互动课件、互动网页、教学动画、微课、实验仿真、研讨型页面、课程设计指导页。
- 用户提到：`课件`、`教学设计`、`大学课程`、`研究生课程`、`AI 助教`、`TTS`、`知识图谱`、`课程大纲`、`培养方案`、`OBE`、`课程设计`、`实验课`、`算法可视化`、`公式推导`、`信号仿真`。
- 用户是高校教师/助教/研究生，目标是用互动化方式讲清一个专业知识难点或一节课。

不要使用：K-12 中小学课程（用 `teachany`）、企业培训/职业技能课、纯 PPT/Word 格式转换、通用网站/App、与教学无关的展示页。

## 与 TeachAny 的关系（一句话）

TeachAnyHE = TeachAny 的**教学设计操作系统（框架层）不变** + **对象/知识组织/视觉/基础设施层换成高等教育**。凡涉及「学习闭环、六问、ABT、认知负荷、脚手架、自适应、探究、评估」的方法全部保留；涉及「学段、课标 node_id、teachany.cn 发布、历史地图、游戏化成就」的 K-12 专属部分全部改造或移除。完整对应关系见 `MIGRATION.md`（迁移说明文档）与本文末「框架对应速查表」。

## 知识体系与培养方案数据在哪？

高等教育没有统一的「课标 node_id」，知识点以**专业培养方案 + 课程教学大纲 + 教材目录**为准。TeachAnyHE 不依赖外部平台，知识图谱本地生成。

| 数据层 | 来源 | 作用 |
| --- | --- | --- |
| **专业培养方案** | 各校各专业培养方案（培养目标/毕业要求/课程体系） | 定位课程在专业中的位置、支撑的毕业要求指标点 |
| **课程教学大纲** | 课程大纲（课程目标/知识点/学时/考核方式） | 界定本课的知识点清单与目标层次 |
| **教材目录** | 主流教材章节目录 | 章节-知识点映射、先修后继关系 |
| **课程知识图谱** | 本地生成 `course-graph.json` | 知识点级先修/后继/Bloom 目标，驱动自适应与知识图谱模块 |

只读示例（无需任何外部凭据）：

```bash
# 查看本课件知识图谱结构（本地 JSON）
cat "$COURSE_DIR/course-graph.json"
```

**课程知识图谱结构**（替代 K-12 课标树）：

```json
{
  "major": "计算机科学与技术",
  "course": "数据结构",
  "chapter": "第5章 树与二叉树",
  "nodes": [
    {
      "id": "ds-tree-bst",
      "name": "二叉搜索树",
      "prerequisites": ["ds-linear-list", "ds-tree-basic"],
      "leads_to": ["ds-avl", "ds-rbtree"],
      "bloom_verbs": ["apply", "analyze"],
      "graduate_attr": "毕业要求3-2 复杂问题建模与求解",
      "definition": "左子树所有结点值小于根、右子树所有结点值大于根的二叉树"
    }
  ]
}
```

## Quick Start

用户：`我给学生讲《信号与系统》的傅里叶变换，做一个能调参数看波形和频谱的页面。`

标准输出路径：

1. **Phase 0 定义**：学生=大三通信/电子信息本科生，先修=电路分析、高等数学、复变函数；课程目标=理解傅里叶变换的物理意义、会用频谱分析信号。
2. 读 `references/higher-ed-framework.md` 确认「培养方案→课程目标→知识点」映射方法与 OBE 目标层次（对应 TeachAny 的课标查询）。
3. 复制 `templates/course-skeleton.html`（分页骨架，已内置 KaTeX 公式渲染 + 学术视觉）。
4. 用「时域一个非周期信号，频域为什么是连续谱？」做问题锚点，接入 Canvas 波形/频谱双视图 + 参数滑块（改变信号时长/幅度看频谱变化）。
5. 按 `tech/animation-toolchain.md` 选动画工具：数学推导/波形演示优先 Manim；算法流程优先 Motion Canvas；电路/信号仿真优先内置 JS 引擎或引用 Python/Jupyter 结果（对应 TeachAny 的动画工具栈，详见 `tech/animation-toolchain.md`）。
6. 接入标准模块：AI 助教、教师卡片、TTS 讲解、section hints、课程知识图谱（对应 TeachAny 五件套）。
7. **学科门类视觉（强制）**：Phase 2 前读 `tech/design-system.md`；`body` 用 `teachanyhe-science` / `teachanyhe-engineering` / `teachanyhe-econ`，理科/工科课不得套用经管/文科的米白典雅风格，反之亦然。
8. **公式渲染（强制）**：所有数学公式用 KaTeX（或 MathJax）渲染，禁止用纯文本/图片代替；推导过程用 `.derivation` 编号步骤组件（高等教育核心需求，K-12 无）。CDN 不可达时用本地 `./assets/katex/`；本地也没有时保留 LaTeX 源码并加可见提示，不得冒充已渲染（见档位 C）。
9. **代码/算法可视化（计算机类强制）**：算法课必须含可运行的算法可视化（步骤高亮 + 复杂度对比），禁止只贴静态代码块。
10. **TTS（按环境档位）**：先探测本机 TTS 能力（见下「环境探测与交付档位」）。档位 A 用 Edge Neural TTS 生成 ≥3 个 `tts/*.mp3`，每个 `data-tts` 段落带 `section` 映射；档位 B 用浏览器 Web Speech 合成并明确标注为合成音；档位 C 跳过音频，保留 `data-tts` 文本与讲解稿。禁止把合成音冒充为真人录音；也禁止在有真实 TTS 能力时偷懒降档。
11. **定稿（强制收尾）**：补齐 AI 助教、课程知识图谱；音频播放器按档位决定——有 mp3 则接连续播放器，无 mp3 则播放器降级为文字稿入口，不得留空按钮。
12. 本地验证后走交付流程（见「交付与发布」）。

## 模式说明

TeachAnyHE 与 TeachAny 一样**只有完整模式**，没有「快速模式」：教学设计与内容基线（六问、ABT、互动、练习、反馈、知识图谱、交付闭环）任何档位都不得省略。

可降级的只有**外部资源依赖类模块**：TTS 音频、动画渲染、AI 助教模型 API、CDN 公式库。这些模块由环境决定档位，不由主观意愿决定。

## 环境探测与交付档位

**先探测，再动手。** 在 Phase 0 完成学生层次定位后，用一条命令或一次尝试确认下列能力是否存在，把结果记入 `PLAN.md`：

| 探测项 | 怎么判定可用 | 对应模块 |
| --- | --- | --- |
| Python 命令 | 终端执行 `python --version` 有版本号返回 | TTS、Manim、质检命令 |
| TTS 引擎 | `edge-tts --version` 可执行，或 `pip show edge-tts` 有输出 | L3 语音讲解 |
| 网络 / CDN | `templates/course-skeleton.html` 内的 KaTeX CDN 可访问 | 公式渲染、在线 TTS |
| 浏览器 | 能打开本地 `index.html` 并支持 Web Speech | 档位 B 合成音、互动验证 |
| 模型 API 凭据 | 环境变量中存在可用的 API Key | AI 助教在线问答 |

按探测结果定档：

- **档位 A（完整）**：Python + TTS 引擎 + 网络均可用。生成 ≥3 个真实 mp3、Manim 动画、在线 AI 助教，交付 `tts/` 目录。
- **档位 B（合成降级）**：无 TTS 命令，但有浏览器。用 Web Speech 运行时合成语音并明确告知学生是合成音；动画改用内嵌 Canvas/SVG；AI 助教走规则式降级链（见 `tech/page-structure.md`）。
- **档位 C（离线最小）**：无网络或完全无脚本环境。公式走本地 `./assets/katex/` 或保留 LaTeX 源码并加提示；不做音频，提供完整讲解文字稿；动画用静态 SVG 分步图。课件仍须可双击打开、互动可用、知识点齐全。

**降档的证据要求**：每个降档项在交付说明中写清「探测了什么、报什么错、改用了什么替代」。主观判断（「先看看效果」「做个简版」）不构成降档理由；反过来，环境明明具备能力却主动降级，同样违规。

## 4-Phase 流程

```text
Phase 0  定义与检索：学生层次/专业/课程/课型，定位课程目标与知识点（对应课标 node_id 查询）
Phase 1  教学骨架：问题锚点 + ABT 叙事 + 互动/评估设计（必须完整，不可跳过）
Phase 2  构建页面：复制模板，填内容，接入标准模块、公式渲染、动画/仿真
Phase 3  验证交付：运行质量检查，浏览器/命令闭环验证，导出/交付
Phase 4  发布/交付：本地交付 + 可选导出（PDF/PPTX/LaTeX/导入 LMS）
```

完整细节见 `phases/workflow.md`；交付细节见 `phases/deliverables.md`。

## 核心规则

1. **模板优先**：新课件先复制 `templates/course-skeleton.html`（分页模板，内置 KaTeX + 学术视觉 + 标准模块接线），不要从空白页手写。复制后删除 `<head>` 内的占位符文档注释块。
2. **学习闭环优先**：每课必须有问题锚点、推导/仿真/证明尝试、即时反馈、总结迁移；视觉炫技不能替代学习设计。
3. **标准模块优先**：AI 助教、教师卡片、TTS/讲解稿、section hints、课程知识图谱优先用标准模块，不重复手写；外部依赖类模块按探测档位选实现。
4. **真实互动**：标题写「互动/仿真/实验/推导/可视化」就必须可操作；静态图不能伪装互动。
5. **公式必须真渲染**：数学/物理/信号类课件，公式一律 KaTeX/MathJax 渲染；推导要分步、可高亮、可回溯，禁止整段公式图片或纯文本堆砌。
6. **代码/算法必须可视化**：计算机类课件的算法/数据结构，必须有可运行的逐步可视化 + 复杂度对比，禁止只贴静态代码。
7. **学科门类视觉必须匹配**：`teachanyhe-stage` meta、`body` class、`:root` 配色三者一致（见 `tech/design-system.md`）。
8. **知识体系必须映射**：每个知识点在 `course-graph.json` 中登记 `prerequisites`/`leads_to`/`bloom_verbs`，并尽量标注支撑的毕业要求指标点（OBE）。
9. **闭环验证**：说「完成/可用」前必须跑命令或浏览器验证，给出关键输出。
10. **资源引用禁止绝对路径**：课件内引用共享脚本/样式/图片必须用相对路径，禁止 `/assets/` 绝对路径（本地与静态托管根路径不一致会 404）。
11. **交付先检测环境**：无导出工具/权限时，不假设能生成 PDF/PPTX；先提示或退回本地 HTML 交付。PPTX 不是必需交付物，当前工具未提供对应能力时直接跳过，不视为豁免。
12. **降档须有证据**：外部资源无法连接必须给出具体报错、已探测项，才允许降档；教学设计与内容基线不得以「环境受限」为由省略。

完整硬规则、基线清单与反模式见 `references/baseline-rules.md`。

## 一、通用教学设计基础（框架层，与 TeachAny 一致）

以下方法对几乎所有专业课程适用，是 TeachAnyHE 的「操作系统」。

### 1.1 开发前回答六问

| # | 问题 | 目的 |
| --- | --- | --- |
| 1 | **学生是谁？**（年级/专业/先修基础） | 定难度、节奏、语言与数学严谨度 |
| 2 | **先修要求是什么？**（前置课程/知识点） | 定是否需要脚手架/前测 |
| 3 | **学完能做什么？**（可观察能力，对应毕业要求指标点） | 把「知道」变成可考核目标 |
| 4 | **真实场景是什么？**（工程/科研/学科前沿问题） | 提供学习动机 |
| 5 | **学生最容易卡在哪？**（概念难点/数学推导/易错点） | 驱动深度理解与错误诊断 |
| 6 | **如何验证学会？**（习题/项目/考试题型） | 定练习与考核方式 |

**输出要求**：六问必须落到课件结构里，不能只当计划笔记。

### 1.2 ABT 叙事结构（And-But-Therefore）

```text
[And]  学生已掌握的知识
[But]  已有知识解决不了的问题
[Therefore] 本课提供的新工具/视角
```

**示例（高等教育）**：

- 数学（最优化方法）：你已经会求一元函数极值（And），但工程问题常含成百上千变量与约束（But），所以要学梯度法与 KKT 条件（Therefore）
- 计算机（数据结构）：你已经会顺序表和链表（And），但海量数据的插入删除效率太低（But），所以要学平衡树/哈希表（Therefore）
- 通信（信号与系统）：你已经会分析正弦稳态信号（And），但真实信号是非周期的（But），所以要学傅里叶变换（Therefore）
- 电气（电路分析）：你已经会欧姆定律（And），但含储能元件的动态电路无法直接求解（But），所以要学时域/复频域分析（Therefore）

### 1.3 内容审计：Essential / Helpful / Decorative

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| 🔴 核心（Essential） | 不学则无法达成课程目标 | 必须出现在主线 |
| 🟡 拓展（Helpful） | 加深理解、考研/进阶必备 | 放入「深挖」「拓展卡片」或补充节 |
| ⚪ 装饰（Decorative） | 对学习目标影响极小 | 尽量删除，避免信息噪声 |

**硬规则**：装饰内容任何一页都不得压倒核心内容。高等教育尤其要警惕「把教材目录照搬到页面」——每节只保留支撑课程目标的 1 个核心问题。

### 1.4 认知负荷管理（Sweller）

| 负荷类型 | 常见表现 | 设计对策 |
| --- | --- | --- |
| **内在** | 概念/定理本身复杂 | 分步、分层、先例后抽象 |
| **外在** | 文字过多、动画混乱、颜色过多 | 限字数、限动效、统一视觉 |
| **相关** | 学生主动组织知识 | 设计预测、比较、分类、迁移任务 |

**推荐指标**：核心信息每卡约 75 词；一个模块=1 个核心问题；新概念后立刻给 1 个例子或 1 个互动。高等数学推导类内容，步骤要能「逐步展开/折叠」，避免一次性灌入整页推导。

### 1.5 Mayer 多媒体原则

| 原则 | 含义 | 课件应用 |
| --- | --- | --- |
| **时空邻近** | 相关图文放一起 | 公式推导紧贴对应公式 |
| **冗余** | 不图文并茂重复同一信息 | 有旁白动画时屏幕只显关键词 |
| **信号** | 视觉线索引导注意 | 关键步骤高亮/箭头/加粗 |
| **分段** | 长内容分段呈现 | 复杂推导/流程拆「点下一步」 |
| **预训练** | 用前先解释关键术语 | 术语首现给一句定义 |

### 1.6 脚手架策略

```text
Level 1（全脚手架）：模板/填空/半成品 → 学生补全
Level 2（半脚手架）：结构提示/关键词 → 学生组织
Level 3（无脚手架）：只给任务要求 → 学生独立完成
```

**应用（高等教育）**：

- 数学推导：完整推导步骤 → 只给关键中间结果 → 独立完成证明
- 编程实现：完整代码框架 → 只给函数签名 → 独立实现
- 课程设计：完整方案模板 → 方案大纲提示 → 独立设计方案

### 1.7 自适应学习设计 ⛔ 必读

自适应不是代码引擎，而是内容设计的底层逻辑。课件必须为不同掌握度的学生规划差异化路径。

#### 四分支内容设计

| 分支 | 触发条件 | 必需内容 | 禁止 |
| --- | --- | --- | --- |
| **review-prereq** | 先修知识掌握度 < 0.5 | ① 先修诊断题 ② 前置课程/知识点回顾卡片 ③ 「继续学习」按钮（永不阻断） | ❌ 不能只是「请先学 XX」 |
| **scaffold** | 当前节点掌握度 < 0.3 | ① 额外分步例题 ② 低 Bloom 层练习 ③ 更多可视化与类比 | ❌ 不能与 normal 路径相同 |
| **normal** | 掌握度 0.3–0.8 | 标准教学流程（ABT→讲解→练习→反馈） | — |
| **challenge** | 掌握度 ≥ 0.8 | ① 跳过基础讲解放到综合 ② 高 Bloom 任务（分析/评价/创造）③ 跨章综合题或开放探究 | ❌ 不能只是「更多同类题」 |

#### 硬规则

- 每个课件至少 2 个自适应触发点（前测后 + 核心练习后）
- scaffold 路径必须有实质性不同内容（不是同内容+提示）
- challenge 路径必须提供更高 Bloom 层任务（不是更多题）
- review-prereq 路径必须提供可操作的回顾资源（链接或内嵌迷你回顾）
- 永不阻断学生——所有分支提供「跳过/继续」

### 1.8 探究式/研讨式学习 ⛔ 必读

高等教育中的「探究」体现为：实验探究、课程设计、研讨课、科研训练、开放性问题。四层深度模型：

| 层级 | 名称 | 教师控制 | 对应场景 | 课件实现 |
| --- | --- | --- | --- | --- |
| **L1 结构化** | 教师给问题+方法+步骤 | 高(80%) | 本科低年级实验 | 分步卡片 + 「下一步」+ 即时反馈 |
| **L2 引导式** | 教师给问题+方向 | 中(50%) | 本科高年级 | 问题卡 → 学生选方法 → 执行 → 对比 |
| **L3 开放式** | 教师只给问题 | 低(20%) | 课程设计/研讨 | 学习记录表 + 评分量表 |
| **L4 自主式** | 学生自拟问题 | 极低(10%) | 研究生/科研训练 | 开放任务 + 汇报 + 同行评议 |

**选择规则**：本科低年级默认 L1、上限 L2；本科高年级默认 L2-L3；研究生 L3-L4。单课件可混合层级。

**硬规则**：课程大纲/培养方案要求「探究/设计/实验」的内容不得改成纯讲授；每个探究活动必须有学习记录表；探究必须有「认知冲突时刻」（初始猜想与实际结果相悖）；理工实验必须明确控制变量三元组（改变什么/保持不变/测量什么）。

### 1.9 学习闭环优先，视觉其次

```text
清晰的课程目标 > 有效的任务设计 > 纠错性反馈 > 好看的页面 > 酷炫动画
```

时间有限时优先保证：真实问题导入、一个可完成的任务、针对性反馈、首尾呼应的总结。

| **经管类** | 模型/决策/方法 | 案例 + 建模 + 决策 | 图表、情景决策、灵敏度分析 | 案例分析 + 建模 |

### 3.2 专业课程「深度理解」框架

| 课程类 | 深度理解优先级框架 |
| --- | --- |
| **数学类** | 直观几何 → 形式化推导 → 一般化/定理化 |
| **计算机类** | 问题目标 → 算法思想 → 复杂度分析 → 实现 |
| **通信类** | 时域现象 → 频域/变换域解释 → 系统建模 → 性能分析 |
| **电气类** | 电路现象 → 电路模型 → 分析求解 → 系统设计 |
| **物理类** | 现象观察 → 模型假设 → 数学方程 → 预测验证 |
| **自动化类** | 系统行为 → 传递函数建模 → 稳定性分析 → 控制器设计 |
| **机械类** | 机构运动 → 受力/运动模型 → 分析求解 → 结构/机构设计 |
| **化学类** | 反应现象 → 机理假设 → 定量计算 → 条件优化 |
| **经管类** | 现实问题 → 模型抽象 → 求解 → 决策与灵敏度 |

### 3.3 五镜法（通用破难点）

| 镜 | 含义 | 最适场景 |
| --- | --- | --- |
| 1. **看**（See It） | 观察现象/图像/数据/波形 | 信号波形、函数图像、实验现象 |
| 2. **拆**（Break It） | 分解结构/步骤/推导 | 定理证明、算法流程、电路分析 |
| 3. **讲**（Explain It） | 澄清因果/机制/规律 | 物理原理、系统行为、模型机理 |
| 4. **比**（Compare It） | 对比相似概念/反例/易错 | 易混淆概念、算法对比、变换对比 |
| 5. **迁**（Transfer It） | 迁移到新场景检验 | 各科「真学会了吗」的检验 |

**示例（高等教育）**：

- 数学「为什么梯度是函数增长最快的方向？」：**看**（等高线图）→ **拆**（方向导数展开）→ **迁**（最速下降法）
- 计算机「为什么二叉搜索树退化成链表？」：**看**（插入序列可视化）→ **比**（平衡 vs 不平衡）→ **讲**（平衡因子）
- 通信「为什么采样要满足奈奎斯特频率？」：**看**（频谱混叠动画）→ **讲**（采样定理）→ **迁**（欠采样后果）
- 电气「为什么电容电压不能突变？」：**看**（RC 充放电波形）→ **讲**（储能元件特性）→ **比**（电容 vs 电感）

## 四、项目制与任务驱动

优先「问题/任务驱动」而非「概念罗列驱动」。

```text
真实任务/现象/问题 → 学生尝试 → 暴露差距 → 引入新知识 → 即时应用
```

**专业课程任务导入示例**：

- 数学：如何用最小二乘拟合一组带噪声的测量数据？
- 计算机：如何设计一个能在千万级数据里毫秒级查找的结构？
- 通信：如何把一段语音信号压缩到原来 1/10 还能听清？
- 电气：如何设计一个能把 220V 交流稳定成 5V 直流的电源？
- 自动化：如何让一个倒立摆不倒下？（控制理论）
- 经管：给定历史收益，如何构造风险最小的投资组合？
